# LibTV 执行器故障处理

目标：锁清理、归档初始化和监督进程崩溃时保留诊断信息，避免工作台持续无效等待。

方案：沿用现有监督进程及任务恢复架构。保留运行环境安全限制，不自动重复提交已有 task_id 的任务。

- [x] 用故障注入测试复现锁清理中断、归档初始化失败、监督进程无回执。
- [x] Node 退出后即使锁清理受阻，也保存 finished 回执及明确错误码。
- [x] 归档初始化置于异常处理内；本地操作回执直接写工作区，不重复初始化归档客户端。
- [x] 每次调用保存独立 supervisor 日志，避免 stderr 丢失。
- [x] 遗留锁、文件权限、锁清理失败、监督进程崩溃时中断自动查询，保留上游任务 ID 并提示继续查询。
- [x] 执行器暂忙和上游暂时不可用仍沿用框架的重试机制。
- [x] 日志目录不可写等启动前 IO 错误也映射为执行器故障，避免退回无限等待。
- [x] 替换任务按 started_at 计算本轮超时；人工恢复已中断的已有上游任务时重开预算及耗时，活跃任务重复点继续不延长预算。原 created_at 不变。
- [x] 协议、计费、恢复、替换任务与生成框架合计 134 项回归测试通过，修改的 Python 文件 Ruff 检查通过。

部署限制：这些改动不解除外部 safe-delete 限制；需要在正常服务运行环境中加载新代码后，恢复原任务的查询。此次实现不清理生产锁、不创建新的上游生成任务。
