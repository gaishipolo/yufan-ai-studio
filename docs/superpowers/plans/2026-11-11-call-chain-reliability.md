# 调用链可靠性修复计划

**目标：** 修复 `docs/reviews/2026-11-11-call-chain-review.md` 的八项发现，保留现有未提交改动与 HTTP 契约，不操作生产任务。

**方案：** 用户确认与启动恢复分离；各渠道优先恢复成功回执；数据库条件更新保护终态；持久队列可靠安排同键后继；非计费查询超时保留恢复路径；工作区 JSON 原子写；新提交授权与已提交查询分开。

**实施方式：** 在当前包含完整未提交功能的工作区实施，避免另建工作树遗漏未提交代码。队列、恢复工作区、授权三个边界分别实施，主任务负责生成编排与集成；不提交、合并或部署。

## 任务及验证

- [x] 队列：先增加 DB handler 内同键后继投递、ack/nack/失租/崩溃恢复测试，确认原实现失败。实现持久化后继交接，保持跨实例去重与租约 fencing；如需表字段，提供 Alembic 迁移。验证 `test_db_queue.py` 和真实 worker/runner 集成。
- [x] 恢复：先增加 prepared 重启不提交、LibTV 成功回执在 DB 空任务号时恢复、确认重提前拒绝已知任务号测试。统一已提交回执恢复，prepared 保持待确认。验证 replacement recovery、billing、channels。
- [x] 工作区：先增加写失败不损坏旧 run.json、投影与执行器租约互斥测试。复用原子 JSON 写并保护投影，不能将旧数据库快照写回正在运行的执行器。验证 archive JSON 写与 LibTV 协议。
- [x] 授权：先增加已提交任务在包停用后继续查询、撤回共享后未提交任务被拒绝测试。保持 owner/回收站访问控制，将新提交授权限定到无上游任务号路径；最终授权检查 source owner/shared。
- [x] 编排：先加入并发旧失败覆盖 success、真实 worker poll 超时后不产生永久 running 孤儿测试。数据库原子状态更新保护终态，并在更新实际生效时发布事件；查询执行预算先于 worker 外层预算到期，从正常重投路径续查。
- [ ] 集成：独立审查每组改动的需求覆盖与实现质量，运行相关后端回归及 Ruff/Mypy，涉及契约则重新导出；运行前端相关回归。修正旧链路文档并在评审报告登记修复结果。

验收：八个反例均有测试覆盖；prepared 不自动收费、已知回执不能重提、成功不会被迟到失败覆盖、DB 轮询/重试不丢后继、查询超时可恢复、投影不暴露半份、授权变化不能阻断已付费续查也不能放行已撤回共享的新提交。
