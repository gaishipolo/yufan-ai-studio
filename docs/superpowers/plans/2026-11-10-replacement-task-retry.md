# 替换任务重试按钮

目标：用户可在「替换任务与调用档案」的失败任务卡片及档案详情中点击「重试」。用户已明确不需要独立测试按钮。

沿用既有 execute API 和提交锁。failed、service_error、needs_login 任务已有 taskId 时仅恢复原任务查询，保留计费模式；没有 taskId 时先打开既有核对弹窗，展示原素材、提示词和计费选择，确认后按原任务 ID 继续准备/提交。timeout 仅在有 taskId 时提供重试。准备失败、提交回执未知、成功、活跃及回收站任务不显示该入口；后端继续负责提交回执未知的防重校验。

实现复用 ReplacementRetry 组件，供列表和详情共同使用。请求中禁用操作，错误沿用工作台和档案的反馈区。更新 failed/timeout 下一步提示，解释已有上游任务只恢复查询，真正的上游失败需核对后新建任务。

- [x] 先添加失败/超时重试、详情入口、未提交核对、权限与回收站、请求失败及防重复点击测试，并运行确认失败。
- [x] 实现共享按钮并接入列表和详情，更新操作提示。接口返回失败状态时展示实际原因，不能以 HTTP 成功误报任务恢复。
- [x] 运行替换工作台相关测试、TypeScript 和定向 ESLint 检查；自查差异。

范围：仅提供用户操作入口，不自动重试生产任务，不创建新测试生成，不新增 API 或绕过鉴权、授权和计费校验。

验证：替换模板目录 7 个测试文件、74 项测试通过；TypeScript 构建检查及修改文件的 ESLint 检查通过。运行中的 5173 服务返回新 ReplacementRetry 模块 HTTP 200、包含重试按钮；通过工作台代理请求 API health 也返回 HTTP 200。组件测试模拟接口，未据此宣称真实上游任务已恢复。
