## 1. 页面定位与用户价值

建议将本页定位为「通用视频生成任务（`video_tasks`）的状态面板」，不是全站所有生成动作的唯一入口：用户在这里确认任务是否还在排队、是否真的生成完、成片能否播放或下载。模板库的替换任务（`ReplacementRun`）是另一套独立体系，当前不进入本页，详见 3.7 与 G19。

| 用户 / 场景 | 需要完成的动作 | 价值与完成标准 |
| --- | --- | --- |
| 有 `task:create` 的创作者 | 描述画面 → 提交生成 → 跟踪排队与进度 | 提交后能看到这条任务，状态与进度与实际一致；刷新、回退、换页都不丢 |
| 等待结果的创作者 | 判断任务还在跑、已完成、还是失败 | 三种状态可区分，排队不等于生成中；失败能看到原因和下一步 |
| 已完成任务的作者 | 预览成片、下载成片、收藏、重试 | 预览是真实产物而非封面；下载得到文件；失败任务可重试且只在可重试时开放 |
| 有 `task:read:all` 的管理者 | 查看他人任务、定位失败任务、必要时重跑 | 能看出任务归属；跨用户重试与调用权限点一致，不因「能看」就「能替人花钱」 |
| 只读账号（仅 `task:read`） | 浏览任务、看详情 | 不出现点了必然 403 的入口；无权限时给明确说明 |
| 模板库替换任务的使用者（`template:read` / `template:use`） | 提交替换、跟踪替换进度、查看成片、人工验收 | 替换任务在 `/templates` 与 `/assets` 查看，本页不出现；两个体系是否需要统一入口见第 10 节 |

首次价值时刻：提交描述后，列表里出现这条任务并显示「排队中」，随后推进到「生成中 / 已完成」，且完成状态是可验证的（能打开产物）。页面显示「已创建」本身不构成价值。

最短流程：创建任务 → 看到这条任务在排队 → 进度推进 → 完成或失败可判断 → 预览 / 下载成片。批量收藏、回收站、二次剪辑都不属于这条最短闭环。

## 3. 已有实现

### 3.1 入口、权限与角标

- `/tasks` 的路由、侧栏项与首页卡片均要求 `task:read`；页面本身不再按 `task:create / task:delete / task:update` 做 UI 门禁。
- 侧栏角标由模块自行实现，每 5 秒以 `scope=mine&pageSize=1` 请求**列表接口**，只取 `stats.running`；为 0 时不渲染。后端另有 `GET /tasks/stats`，前端未使用。
- 任务页是 `VideoTask`（通用视频生成）的唯一列表入口；创建、详情、收藏、重试都在本页完成，没有独立详情路由。模板库的替换任务不在此列，见 3.7。

### 3.2 列表、筛选与分页

- 筛选条件全部写入 URL：`status / keyword / sort / scope / auth / page`；改任一条件会清掉 `page` 回到第 1 页。
- 关键词输入 300ms 防抖后 `replace` 写入 URL；`keyword` 只做「输入 → URL」单向同步。
- 状态标签四项：全部 / 进行中 / 已完成 / 失败，计数字段取 `stats`；`stats` 为空（加载中或失败）时不显示 0，而是不渲染数字。
- 无 `task:read:all` 时，范围下拉只保留「我的任务」；若 URL 中残留 `scope=all / team`，数据返回后会回落到 `mine`。
- 「仅授权」开关对应后端 `onlyAuthorized`，实际含义是**只显示可下载（已成功且有产物）的任务**，不是权限过滤。
- 每页固定 48 条，`pageSize` 不写入 URL；`Pager` 只有一页时整条隐藏，页码越界会自动回写纠正，总数未知（`0`）时不回写。
- 列表有缓存时切换筛选会保留上一页数据（`keepPreviousData`），不会退回整页骨架。

### 3.3 卡片与选择

- 卡片展示封面、状态角标（**`completed` 不显示角标**）、左上「预览」标签、时长（在途时不显示）、标题两行、模型、比例与创建时间。
- `queued / running` 显示进度条与百分比；`queued` 也走这条分支，因此会显示 `0%`。
- 整卡是一个铺满的 `button`（读屏名为「查看任务：标题」），右上勾选框是独立按钮并阻止冒泡；勾选框默认 `opacity-0`，仅 `group-hover` 显示，选中后常显。
- 选择状态独立于筛选与分页：切换标签或翻页不会清空已选项；「全选」只作用于当前页 `items`。
- 封面加载失败会回落为渐变占位（`CoverImage`）；但 `coverUrl` 目前来自创建时的 `picsum.photos` 占位地址，未生成完时不是真实首帧。

### 3.4 创建

- 弹窗字段：画面描述（必填，前端给红框与文案）、模型、时长、比例；模型 / 时长 / 比例选项全部来自 `GET /models`，切换模型会收敛到该模型支持的档位。
- 提交载荷只含 `prompt / model / durationSec / aspectRatio`；接口支持的 `title`、`referenceAssetIds`、`stylePreset` 未在表单中出现。
- 成功后 toast「任务已创建，正在排队生成」，关闭弹窗，列表失效并切回「全部」、清空选择；不定位新任务，也不提示预计等待。
- 失败只 toast 后端 message，弹窗保留输入；没有字段级错误映射（如模型下架、时长越界由后端返回 400）。

### 3.5 详情、重试、收藏与下载

- 详情通过 `GET /tasks/:id` 拉取，在途时同样 2.5s 轮询；弹窗展示任务 ID、状态、模型、比例、时长、创建时间、画面描述，失败时额外显示 `errorMessage`。
- 未展示 `authorName`、`startedAt`、`updatedAt`、`stylePreset`、`referenceAssetIds`。
- 「重新生成」对所有状态可点，只按 pending 显示 loading；后端仅允许 `failed`，其他状态返回 409。
- 「收藏 / 取消收藏」调用真实接口并 toast 结果；「下载成片」在 `downloadable=false` 时禁用并 toast「成片尚未生成完成」，可点时只 toast「等待接入下载接口」。
- 弹窗没有播放器，只有封面图与一段说明文字：「播放器与下载走的是占位逻辑」。
- 列表工具栏的「收藏」不发请求，直接 toast「已加入收藏」；「回收站」直接 toast「回收站为空」；「下载」只 toast「待接入下载接口」。

### 3.6 接口与数据事实

- 后端 8 个接口与前端 `task.api.ts` 一一对齐：列表 / 统计 / 详情 / 创建 / 局部更新 / 收藏切换 / 重试 / 批量删除。
- 数据范围只有 `task:read:all` 一个开关；没有它时 `scope=all / team` 静默降级为本人数据，详情与删除用同一判定。`task:retry:any` 与之独立，重试他人任务需要它。
- 关键词匹配 `title / model / id`（不匹配 `prompt`）；排序都以 `id` 收尾，翻页边界稳定。
- `POST /tasks/{id}/retry` 返回 `{id, status, updatedAt}`，不是整份任务；前端类型已按此定义。
- 批量删除是**物理删除**，返回 `deleted` 与 `skipped`；`skipped` 包含「不存在」与「无权限」两种原因，服务端不区分对外文案。
- `TaskOut` 不包含 `outputUrl`；`downloadable` 只表示「已成功且有产物」。因此当前前端拿不到任何可播放 / 可下载的资源地址。
- mock 模式下 `task.mock.ts` 会按时间推进状态，`pageSize` 默认 24，与页面固定 48 不一致；mock 行为不能当作真实轮询证据。

与文档的差异与口径提醒：

1. 页面描述写「完成后视频可直接收藏、下载或二次剪辑」，当前只有收藏是真实动作，下载与二次剪辑均无入口。
2. `API.md` 已有 `GET /tasks/stats`，但角标走列表接口；两处统计口径（`running` 单项 vs 全量）需在产品上统一。
3. `onlyAuthorized` 在文档中写「仅显示可下载任务」，界面上写「仅授权」，容易被理解为权限过滤。
4. 工具栏「回收站」没有对应接口，`DELETE /tasks` 是硬删除；不能把「回收站为空」当作已有能力的说明。

### 3.7 与模板库替换任务的关系

结论：两者**没有关联**，是并行且互不感知的两套任务体系。当前不存在外键、共享 ID、共享状态或统一列表；`api/src/modules/template/` 对 `VideoTask` / `video_tasks` 零引用，`/tasks` 与 `/replacement-runs` 之间也没有交叉查询。

| 维度 | 任务中心 `/tasks` | 模板库替换 `/templates` |
| --- | --- | --- |
| 数据存储 | `video_tasks` 表（SQLAlchemy） | Z 盘 `catalog/runs/<id>.json` 档案＋输入快照目录 |
| 领域对象 | `VideoTask` | `ReplacementRun` / `ReplacementManifest` |
| 页面入口 | 任务中心、首页卡片 | 模板库「替换任务记录」；成片另在素材页结果区展示 |
| 生成链路 | `generation.runner` + `VideoGenerationPipeline`（`KIND_VIDEO`） | `ReplacementPipeline`（`KIND_REPLACEMENT`）+ `replacement_worker` |
| 状态集合 | `queued / running / completed / failed` | 18 种展示态（`replacement.labels.ts`）：准备、排队、上传审核、提交、生成、下载、成片已保存、结果未知、等待免费等 |
| 进度 | `progress 0–100`，列表 2.5s 轮询 | `progress`，目录轮询（存在活跃 run 时） |
| ID | 服务端生成的 `VideoTask.id` | 32 位十六进制 run id；`task_id` 是**上游 LibTV 任务号**，不是 `VideoTask.id` |
| 计数 / 费用 | 无积分字段 | `estimated_credits / credits`、`billing_mode`、自动重试上限 |
| 人工验收 | 无 | `review_status` + `ReplacementReview`（版本冲突需重新核对） |
| 产物 | 仅 `downloadable` 标记，**无产物地址** | `/replacement-runs/{id}/output` 直接返回文件 |
| 权限 | `task:read / create / update / delete / read:all / retry:any` | `template:read / write / use / review`，另叠加 `asset:read` |
| 归属 | `authorId` + `task:read:all` 跨用户 | `owner_id`，按调用档案隔离 |

由此产生的事实：

- 模板库提交替换后，任务中心**不会**出现任何记录；通用视频任务也不会出现在模板库的「替换任务记录」里。
- 角标、统计、搜索、分页互不覆盖；替换任务的失败重试与「继续查询已有任务」只在模板库提供。
- 同一份替换成片可能同时出现在模板库记录与素材页结果区，但都不在任务中心；这是当前唯一的跨页面可见产物，仍不是同一对象。
- 「任务」在项目里指两种东西：`VideoTask`（通用生成）与 `ReplacementRun`（替换调用档案）。文案、权限、接口都应按对象区分，不能用「任务中心」概括全部生成动作。
- 若目标是「一个地方看到所有生成」，需要显式设计聚合层；不能在 `/tasks` 里直接 `union` 两类数据——字段、状态、权限、分页都无法对齐，见第 10 节。

已落地的最小互链（2026-11-06，未新增接口、未改存储）：

- 任务中心标题下说明「本页只包含通用视频生成任务」，并对有 `template:read` 的账号给出「去模板库查看替换任务」链接；无权限时不渲染，避免送到 403。
- 模板库「替换任务与调用档案」区说明只含替换任务，并对有 `task:read` 的账号给出「任务中心」入口；反向同样按权限收敛。
- 这只是可发现性修复，不改变两套体系的数据与状态：替换任务仍不在 `/tasks` 的列表、统计、搜索、角标中。

## 4. 已知缺口与文档差异

| 编号 | 事实 / 差异 | 用户影响 | 建议优先级 |
| --- | --- | --- | --- |
| G01 | 「进行中」标签只筛 `status=running`，`queued` 任务只在「全部」里出现；标签计数字段含 `queued`，四项相加不等于「全部」 | 刚提交的任务在「进行中」里找不到；用户怀疑没提交成功，重复创建 | P0 |
| G02 | 工具栏「收藏」不发请求却提示成功；「回收站」无接口却提示为空；「下载」只提示待接入；`DELETE /tasks` 与 `task:delete` 完全没有界面入口 | 三个批量主按钮都是占位或假成功；用户以为已收藏、以为有回收站可恢复 | P0 |
| G03 | 下载链路缺失：`TaskOut` 不暴露产物地址，后端无下载 / 文件接口，卡片也没有下载入口 | 页面承诺的「下载成片」无法完成，成片只能看封面 | P0 |
| G04 | 详情弹窗只处理 `isLoading`，未处理 `isError`：请求失败时 `task` 为空，骨架屏会永久停留 | 403 / 404 / 断网时表现为卡死，没有原因也没有重试 | P0 |
| G05 | 「重新生成」不判断状态；后端仅允许 `failed`，其余状态 409 | 已完成任务点重试必然报错；错误只在 toast 中出现 | P0 |
| G06 | 卡片标「预览」，弹窗只有封面图与占位说明，没有播放器 | 「预览」名不副实，用户无法确认成片内容 | P0 |
| G07 | 选择状态不随筛选、分页、清空条件复位，「全选」只覆盖当前页；下载计数使用 `selected.size` | 会对看不见的任务执行批量操作，计数与实际可见项不一致 | P0 |
| G08 | 刷新按钮用 `isFetching` 驱动旋转，而列表在途时会每 2.5s 后台轮询，图标持续旋转；点击后无条件 toast「已刷新」 | 「正在刷新」与「已刷新」都不代表真实结果 | P0 |
| G09 | URL 参数 `status / sort / scope` 直接 cast 后透传；非法值触发后端 422，页面进入错误态且重试无法恢复；`scope=team` 在有权限时下拉无对应选项 | 分享或手改链接后页面不可用，且看起来像服务故障 | P1 |
| G10 | 关键词只做「输入 → URL」单向同步；浏览器后退 / 前进改变 `keyword` 后输入框仍显示旧词 | 界面条件与实际结果不一致，用户以为搜索没生效 | P1 |
| G11 | 空态只有一种文案「没有匹配的任务」，首次无任务、筛选无匹配、权限内本就为空共用同一分支，且没有创建 / 清空筛选入口 | 新用户不知道下一步；筛选空被误解为没有任务 | P1 |
| G12 | 失败卡片只显示红色「生成失败」，`errorMessage` 仅在详情里；卡片级没有重试或「查看原因」 | 批量失败时要逐条点开，无法快速判断是否同一原因 | P1 |
| G13 | 页面只校验 `task:read`；创建、收藏、重试、删除按钮不做 `useCan` 门禁 | 只读账号能看到并触发必然 403 的操作，报错发生在提交之后 | P1 |
| G14 | 角标只统计 `running`，排队任务不计入；`/tasks/stats` 未被使用；统计口径与标签不一致 | 有排队任务时角标可能为 0，用户以为没有在跑的任务 | P1 |
| G15 | 跨用户范围下卡片与详情都不显示 `authorName`；详情不显示 `startedAt` / `updatedAt` | 管理者分不清任务归属，也无法判断卡了多久 | P2 |
| G16 | 勾选框仅 hover 显示，键盘聚焦时 `opacity` 仍为 0；批量结果没有逐条反馈，也没有成功后清空选择的规则 | 键盘用户看不到选择控件；批量操作后状态不明 | P1 |
| G17 | 创建表单未覆盖 `title / referenceAssetIds / stylePreset`；创建成功不定位新任务 | 无法命名、无法图生视频、无法套风格；新任务可能落在第 2 页 | P2 |
| G18 | 页面无任何页面级测试（仅 `TaskCard` 有测试），空 / 错 / 分页 / 轮询分支未覆盖 | 状态契约改动没有回归保护 | P1 |
| G19 | 两套任务体系无数据关联：替换 run 不写 `video_tasks`，`/tasks` 不读取 run 档案，两边无外键、无聚合列表；已补互链与页面说明（2026-11-06），但替换任务仍不出现在任务中心 | 用户在两处看到两套「任务」，不知道哪套包含自己的工作；替换成片在任务中心查不到 | P1（若确认要统一则升 P0） |

补充说明：G02 与 G03 同属「批量动作没有真实链路」，但修复路径不同——G02 是前端不要假装成功，G03 需要新增后端契约；不要用同一个「待接入」文案掩盖两者。

G19 与 G03 不能互相替代：即使补上 `VideoTask` 的产物地址，模板替换任务仍然不会出现在任务中心；即使把替换任务聚合进来，通用任务依旧缺少下载接口。两者是不同层面的缺口。

## 5. 建议需求范围

### 5.1 必须有：让已有事实可判断、可执行（P0）

| 编号 | 目标行为 | 输入 / 输出与完成条件 |
| --- | --- | --- |
| R01 | 状态口径与标签一致 | `queued` 有明确归属（并入「进行中」或单独「排队中」）；标签数字与「全部」自洽；角标统计口径与标签一致 |
| R02 | 批量动作只做真实的事 | 未接入前隐藏或明确禁用「下载 / 收藏 / 回收站」，不使用成功文案；已接入后保留逐条结果 |
| R03 | 成片可预览、可下载 | 详情有真实播放能力；下载得到文件而非 toast；不可下载时说明原因（未完成 / 无产物 / 无权限） |
| R04 | 详情错误可见、可恢复 | 失败时显示原因与「重试」「关闭」；403 / 404 文案区分；不再无限骨架 |
| R05 | 重试只在合法状态开放 | 仅 `failed` 可点；其他状态禁用并说明；提交中禁用防重复，成功后就地更新状态 |
| R06 | 选择范围明确且可清空 | 切换筛选 / 翻页时选择复位或明确提示跨页保留；提供「取消选择」；批量动作只作用于可见且已选中的任务 |
| R07 | 刷新反馈真实 | 后台轮询不驱动「刷新」按钮；手动刷新成功 / 失败分别反馈，失败保留旧数据 |
| R08 | 删除有明确入口（若纳入本期） | 二次确认 → 调 `DELETE /tasks` → 展示 `deleted` 与 `skipped` 的逐条结果；不把硬删除说成进回收站 |

若本轮不做下载与删除，R02 要求至少把占位按钮改为不可用并说明「暂未开放」，不能让用户以为操作成功。

### 5.2 应该有：可查找、可解释（P1）

- URL 参数白名单校验：非法 `status / sort / scope` 回落到默认值并清理 URL，不发注定 422 的请求；`scope=team` 在未实现前不出现在可选项中。
- 关键词双向同步：URL 变化（后退 / 前进 / 外链）要回填输入框，且不触发新的防抖写入。
- 空态分流：首次无任务 → 提供「创建任务」；筛选无匹配 → 提供「清空筛选」并保留范围说明；权限内为空 → 说明可见范围。
- 失败卡片直接给原因摘要与「重试」；同一错误可在卡片与详情复用同一文案，不新造第二套错误码。
- 权限门禁：`task:create / task:update / task:delete` 决定按钮显隐；无权限时给可理解的说明，不只靠后端 403。
- 跨用户可见性：`scope=all` 下卡片与详情显示作者；详情补 `startedAt`（已耗时）与 `updatedAt`。
- 创建表单补齐标题与参考素材 / 风格预设（按产品优先级择一）；成功后高亮或定位新任务，失败给字段级提示。
- 批量收藏若保留，需新增批量契约或逐条调用并汇总结果；不能以 toast 代替请求。
- 明确两套任务体系的边界：任务中心只负责 `VideoTask`，在页面说明「替换任务请在模板库查看」并提供跳转；若要聚合，单独定义视图、状态映射与权限口径，不能把两套状态直接混排。
- 为 `TaskCenterPage` 补状态测试：空 / 错 / 分页越界 / 轮询停止 / 选择复位 / 权限收起。

### 5.3 以后再做 / 本轮不默认纳入

回收站与软删除、任务重命名、批量打包下载（ZIP）、二次剪辑入口、团队范围（`scope=team`）、任务分享链接、跨模块统一产物库、跨体系任务聚合（任务中心统一展示替换任务）、导出任务清单、失败自动重试与费用策略。

这些能力都不是「看到任务并拿到成片」这条闭环的必要前置。保留已有能力：URL 承载筛选、2.5s 条件轮询、`task:read:all` 与 `task:retry:any` 分离、删除返回 `skipped`、重试最小出参。若后续做回收站，必须先把 `DELETE /tasks` 从物理删除改成软删除并定义保留期、恢复与彻底删除规则，不能只加一个前端入口。

## 6. 建议页面结构

从上到下：

1. 页面标题与价值说明（不承诺尚未具备的下载 / 二次剪辑）。
2. 工具行：范围、仅授权、排序、刷新；批量动作按「已选 N 条」出现，未选择时禁用而非报错。
3. 状态标签与统计：数字与「全部」同口径，`queued` 有归属。
4. 搜索行：关键词、刷新状态、真实总数（未知显示 `—`）。
5. 任务卡片网格：状态、进度、失败原因摘要、归属（跨用户时）、选择控件。
6. 分页条。
7. 创建任务弹窗、任务详情弹窗（详情承担播放、下载、重试、收藏）。

批量动作建议收进「已选 N 条」的工具条，避免 8 个按钮平铺；未选择时只保留「创建任务」。

页面说明需注明本页只包含通用视频生成任务；模板库的替换任务在 `/templates` 查看（除非第 10 节决定做聚合）。

## 7. 页面状态契约（目标，尚未实现）

| 区域 | 状态 | 触发条件 | 内容或文案 | 用户动作 | 禁用与恢复 |
| --- | --- | --- | --- | --- | --- |
| 列表 | 首次加载 | 无缓存且请求 pending | 卡片骨架；统计不显示 0 | 等待 | 成功或失败后退出；不出现空态 |
| 列表 | 首次无任务 | 请求成功，无任何筛选，`total=0` | 「还没有任务」＋创建引导 | 创建任务 | 有 `task:create` 才给按钮，否则说明权限 |
| 列表 | 筛选无匹配 | 请求成功，`total=0` 且存在关键词 / 状态 / 仅授权 | 「没有符合条件的任务」 | 清空筛选 / 改条件 | 保留当前条件说明，不提示「创建第一条」 |
| 列表 | 正常 | 请求成功且有数据 | 卡片与真实总数、标签数字 | 打开、选择、翻页 | 后台刷新不清空列表 |
| 列表 | 首次错误 | 请求失败且无缓存 | 「任务加载失败」＋原因 | 重试 | 不展示空态、不显示 0 条 |
| 列表 | 后台刷新 | 有缓存且正在轮询 / 手动刷新 | 保留内容，轻量「更新中」 | 继续操作 | 刷新按钮不因轮询常转；失败时标注「更新失败，以下为上次结果」 |
| 列表 | 分页越界 | 当前页大于实际总页数 | 回到最后一页 | 自动纠正 | `total` 未知时不回写 |
| 卡片 | 排队中 | `status=queued` | 「排队中」，不展示百分比进度 | 打开详情 | 不把排队写成生成中；角标计入 |
| 卡片 | 生成中 | `status=running` | 进度条＋真实百分比 | 打开详情 | 进度只增不减；不提前显示 100 |
| 卡片 | 失败 | `status=failed` | 红色状态＋原因摘要 | 查看详情 / 重试 | 仅失败可重试；重试提交中禁用 |
| 卡片 | 已完成 | `status=completed` | 明确的完成标识＋时长 | 预览、下载、收藏 | 无产物时不给下载，说明原因 |
| 选择 | 未选择 | `selected.size=0` | 批量动作禁用或不出现 | 勾选卡片 / 全选 | 点击批量动作只提示选择，不假装执行 |
| 选择 | 跨筛选 | 已选任务不在当前结果中 | 「已选 N 条，其中 M 条不在当前筛选」 | 清空选择 / 仅对当前页操作 | 批量动作范围必须可见；不得静默包含不可见项 |
| 详情 | 加载 | 打开且无缓存 | 骨架 + 标题占位 | 关闭 | 不误显示「任务不存在」 |
| 详情 | 错误 | 请求失败 | 区分 403 / 404 / 网络失败的文案 | 重试、关闭 | 不无限骨架；不可把错误画成加载 |
| 详情 | 重试不可用 | 状态非 `failed` | 按钮禁用＋「仅失败任务可重新生成」 | 无 | 不在点击后才报 409 |
| 详情 | 重试提交 | 已点击且请求在途 | 按钮 loading，禁止重复点击 | 等待 | 成功后状态变「排队中」并刷新列表 |
| 详情 | 下载不可用 | `downloadable=false` | 按钮禁用＋原因（未完成 / 无产物） | 无 | 不提示「开始下载」 |
| 详情 | 下载 / 预览进行中 | 已触发文件请求 | 进度或加载态 | 取消 / 等待 | 失败给可重试提示，不覆盖已加载内容 |
| 批量 | 部分失败 | 返回 `deleted` 与 `skipped` | 「成功 X 条，未处理 Y 条」逐条列出 | 重试失败项 | 已成功项不重复提交；未知结果先刷新核对 |
| 全局 | 无权限 | 缺少对应权限点 | 入口不出现或明确说明 | 无 | 不只依赖后端 403 |

键盘可操作全部控件；弹窗打开后焦点进入、关闭后归还；状态变化使用可访问提示；动画遵循减少动态效果偏好。以上为目标验收条件，不代表现有基础组件已全部满足。

## 8. 数据与接口边界

| 范围 | 复用 / 影响 |
| --- | --- |
| 列表、状态、分页 | 复用 `GET /tasks`；`stats` 与 `canReadAll` 已在同一响应中，无需新接口；改标签口径需同步 `TaskStats` 字段含义 |
| 角标 | 可改用已有 `GET /tasks/stats`，但要确定 `queued` 是否计入；不要同时维护两套统计口径 |
| 预览 / 下载 | 需新增产物地址或文件接口（沿用素材模块 `FileResponse` 模式，带鉴权与归属校验），并把字段加入 `TaskOut`、`studio` 类型与 `docs/API.md`；`coverUrl` 不能当视频地址 |
| 重试 | 复用现有接口；前端按 `status` 禁用。保持最小出参 `{id,status,updatedAt}`，不因前端方便而返回整份任务 |
| 收藏 | 单条接口已存在；批量需新增批量端点或逐条调用并汇总，不能伪造成功 |
| 删除 / 回收站 | 现有 `DELETE /tasks` 为物理删除并返回 `skipped`；软删除需新增字段、列表默认过滤、恢复与彻底删除接口，属于独立契约变更 |
| 权限 | 保持 `task:read:all`（可见 / 可删）与 `task:retry:any`（可替人重跑）分离；前端门禁只做展示，不替代后端校验 |
| 创建 | 补齐 `title / referenceAssetIds / stylePreset` 时同步表单校验与 `CreateTaskIn` 限制（标题 200、参考素材最多 20） |
| Mock | mock 数据推进与真实 worker 不同步；涉及状态契约的验收以真实后端为准，mock 只用于布局验证 |
| 模板库替换任务 | 独立存储（Z 盘 run 档案）与独立接口 `/replacement-runs`；任务中心不读取 run 档案。若要聚合，建议新增只读聚合视图，保留两边主表与状态词表，不做数据迁移；不得把 run id 当 `VideoTask.id`，也不得用 `task:*` 权限直接放开 `template:*` 数据 |

不得为了本页方便而放宽归属校验、跳过重试费用门禁、把 `queued` 直接写成 `completed`，或在列表接口里返回他人任务的 `prompt`。

## 10. 待决定与验证记录

以下问题不阻碍本轮文档交付；进入对应实现阶段前确认即可：

| 决策 | 当前建议 / 原因 |
| --- | --- |
| 「进行中」是否并入 `queued`？ | 建议并入或独立「排队中」；否则刚提交的任务找不到，是最容易被当成「没提交成功」的缺陷 |
