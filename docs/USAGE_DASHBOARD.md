# 用量看板

> 2026-11-22 落地。之前它是一个**占位页**：前端有路由、侧栏有入口，后端一个接口都没有，
> 路由守卫里它是唯一的豁免项。现在它是本仓库第一个**跨模块聚合**的页面。

## 0. 一句话

看板回答一个问题：**这段时间里，这套系统产出了多少东西、产得稳不稳、是谁产出的。**

它不回答「现在有什么任务」——那是任务中心的事。它是**事后对账**的页面。

## 1. 页面功能模块划分

页面分两层：**页签**（换内容）与**筛选条**（改同一件事的做法）。两者都不是为了好看，
是因为读者不同。

### 1.1 筛选条（三组互斥选项，各管一件事）

| 控件 | 取值 | 影响谁 | 挂在 URL 上的键 |
|---|---|---|---|
| 时间区间 | 近 7 / 30 / 90 天 | 概览 + 明细 | `range` |
| 趋势粒度 | 按日 / 按周 | **只**影响趋势图 | `granularity` |
| 数据范围 | 我的 / 全部成员 | 概览 + 明细 | `scope` |

**筛选条件全部由 URL 承载**（与任务中心同一条规矩）。看板上那张「上个月、按周、
全部成员」的图是要被贴到群里的 —— 链接得能复现，回退也得能用。

粒度只对趋势图有意义，所以它**只在概览页签下出现**。把一个对当前视图无影响的
控件放在那儿，用户会以为它对下面那张表也生效。

### 1.2 概览页签

页面分三层，自上而下是「先结论、再过程、再拆解」：

| 层 | 模块 | 内容 | 为什么这么切 |
|---|---|---|---|
| 结论 | **主卡**（占 2/3 宽） | 已产出数量（大字）· 视频时长 · 发起次数 · 成功/失败/进行中 三段比例条 | 页面上真正的结论只有一个：**产出了多少**。给它最大的字号和最多的宽度 |
| 结论 | **比率卡**（占 1/3 宽） | 成功率（大字 + 进度条）· 成功 / 失败计数 | 比率和总量是两种结论，并排放，一眼对照 |
| 过程 | 趋势 Panel | 堆叠柱：已产出 / 失败 / 进行中 | 回答「什么时候产的」。柱子是三段而不是一根 —— 只看总量看不出「量上去了但全是失败」 |
| 拆解 | 构成 Panel | 按 模型 / 方式 / 使用人 / 模板 / 状态 切换 | 回答「谁产的、用什么产的」。这些维度是**切换**不是**堆叠**：它们是同一批数字的不同切法，同时铺开会互相盖住 |
| 关系 | 模板 × 使用人 Panel | Top 10 模板 × Top 10 使用人的热力表 | 回答「谁在用哪张模板」。单元格是尝试次数，颜色越深越多；只有带模板来源的记录才进这张表 |

**为什么不是四张一样大的卡**：四张等大的卡读起来是「四个并列的事实」，用户得
自己决定哪个重要 —— 那等于没做信息层级。所以「已产出」被放大，「发起次数」和
「平均时长」降级成主卡底部的一行小字（它们是分母和参照，不是结论），「成功率」
独占一格。

层级靠**字号和位置**建立，不靠标签解释：哪张卡更大，眼睛就知道哪张是结论。

趋势图是**自绘**的（flex + 百分比高度），没有引图表库：这个页面只需要一种图形，
引一个库的成本（包体、主题不匹配、渲染风格和仓库其余部分不一致）大于自己画。

#### 1.2.1 颜色与字号的规范

同一件事在一个页面里只能是**同一个颜色**，所以「已产出」在三处出现时是同一个
蓝（`primary`）：主卡的比例条、趋势图的柱子、构成图的条。

| 元素 | 取值 | 说明 |
|---|---|---|
| 已产出 / 成功 | `primary`（蓝） | 主数据色 |
| 失败 | `danger/70` | 面积小，用不透明度压一档，避免刺眼 |
| 进行中 | `line-strong`（中性灰） | 没有产出，不该抢注意力 |
| 成功率条 | `ok` ≥90% / `primary` ≥70% / `warn` <70% | 颜色是**编码**不是装饰：不用一句话解释「这一格好不好」 |

字号只用字阶里的四档：`display`（26）给唯一的主数字、`title`（19）给次级数字、
`body`/`meta` 给标签与小字。数字一律 `font-mono tabular-nums` —— 这一列要能竖着
扫，比例字体的数字上下跳动，看不出「哪个更大」。

#### 1.2.2 响应式

| 断点 | 布局 |
|---|---|
| `< 640px` | 单列；筛选条三组各占一行；趋势图横向滑动且**默认停在最右**（时间轴右端才是「最近」） |
| `640–1023px` | 指标区两列（主卡与比率卡各占整行）；构成面板的维度切换落到标题下一行 |
| `≥ 1024px` | 指标区三列（主卡 2 + 比率卡 1）；三组筛选条一行排开 |

窄屏时 `PanelHeader` 的操作区会换到标题下一行 —— 否则「用量构成」四个字会被
分段控件挤成两行（标题被压成「用量构 / 成」）。

### 1.3 明细页签

一张表：时间（UTC）/ 来源 / 标题 / 模型 / 数量 / 时长 / 状态 / 使用人，20 条一页。

**为什么用表格而不是卡片**：明细是**对账**用的 —— 用户想知道「哪一条、什么时候、
出了几个、多长」。卡片会把每一行摊成一大块，扫一列数字（时长、次数）要竖着滚一屏；
表格让同一列对齐，才扫得动。

### 1.4 为什么不做成一个页面

管理者看**概览**（多少、趋势、谁用得最多），执行的人看**明细**（我昨天那条成片
到底有没有算进去）。混在一屏里，明细的表格会把上方的指标卡挤到折叠线以下 ——
首屏变成一张要滚的表，趋势图反而没人看。

## 2. 口径（只有一份实现）

口径散在两个地方就是灾难：口径一改，图表和列表必然对不上。所以**全部定义在后端**，
前端只负责显示。

| 字段 | 含义 | 注意 |
|---|---|---|
| `total` | **尝试**次数 | 含失败与进行中 |
| `succeeded` / `failed` / `pending` | 三态计数 | 状态词表不同（视频 `completed` / 生图 `succeeded`），由 `classify_status` 统一 |
| `quantity` | **已产出**数量 | 视频按条、生图按张；**只计成功** |
| `durationSec` | 已产出视频总时长 | **只计成功** |
| `successRate` | `succeeded / total` | |
| `avgDurationSec` | `durationSec / succeeded` | 分母是成功数，不是尝试数 |

**失败的任务不计时长、不计数量** —— 用户没拿到东西，不该为它付账。

**模板来源**是提交时冻结的 `templateKey` / `templateVersion` / `templateName`：
`templateKey` 是身份（改名不变），卡片累计次数按它归并；看板的模板维度与
「模板 × 使用人」只统计带 key 的记录，直接创建的任务/生图不进入模板关系图。
模板卡片显示的是**累计尝试次数**（含失败/进行中），与看板按时间区间的数字
口径不同，文案上要写「累计」。

「按模板」维度里，没有模板 key 的记录按入口命名：视频 = **生成工作台**，
生图 = **生图**。历史记录由 `scripts/backfill_template_identity.py` 一次性
回填：同名模板唯一（或同归属唯一）、且模板创建时间早于任务时才写入；歧义
跳过并报告，不回填的保持直接来源。

### 2.1 时区一律 UTC

区间、桶边界、界面显示全部 UTC。原因很实在：一条 UTC 23:00 的记录按本地时区显示
是「第二天 07:00」，而它在折线图上属于**前一天**。用户会看到「图表在这一天有条
记录，列表里却是另一天」。一套时区看到底，不要给用户「看时区」这个负担。

## 3. 数据来源：可插拔注入口

看板要的是「所有生成能力的用量」，而生成能力天然分散在多个业务模块：视频任务在
`modules/task`，生图作业在 `modules/image`。业务模块之间**不许互相 import**
（`tests/test_architecture.py` 用 AST 守着这条线），所以看板不能自己去查那两张表。

于是开了个**多实现**注入口：`api/src/core/ports/usage_metrics.py`。

```
core/ports/usage_metrics.py     ← 契约 + 注入口 + 共享纯函数
  ├── modules/task/usage_provider.py     register_usage_metrics("video", ...)
  └── modules/image/usage_provider.py    register_usage_metrics("image", ...)
modules/usage/service.py         ← 只认契约，把各来源结果合并成一张图
```

两端互不认识：来源方不知道自己被谁读，看板不知道来源方的表长什么样。

### 3.1 已接上的来源

| key | 模块 | 记什么 |
|---|---|---|
| `video` | `modules/task` | 视频任务：条数、总时长、模型、文生/图生 |
| `image` | `modules/image` | 生图作业：张数、模型 |

### 3.2 加一个新来源（音频 / 数字人 / 外部供应商…）要做什么

**五步，看板一行都不用改**：

1. 在自己的模块里新建 `usage_provider.py`，实现 `UsageMetricsProvider`：
   - `aggregate(query) -> UsageAggregate`
   - `records(query) -> UsageRecordPage`
2. 读自己的表，归一成 `UsageRow`（`created_at` / `status` / `model_id` /
   `model_name` / `quantity` / `duration_sec` / `owner_id` / `owner_name` /
   `kind`；有模板来源时再填 `template_key` / `template_name` / `template_version`）。
3. 交给共享的 `aggregate_rows(source, rows, granularity)` —— **口径不要自己再写一遍**。
4. 在自己模块的 `__init__.py` 里 `register_usage_metrics("audio", AudioUsageProvider())`。
5. 前端补一个 `sourceLabel()`（`entities/usage/model/source-labels.ts`），并在
   `modules/<x>/mock.ts` 里补 mock 路由。

看板的 `sources` 会自动多出一路，`sources` 为空 → 非空的提示也会自动消失。

### 3.3 未注册是合法状态

只跑单元测试、或某个能力还没接上时，注入口可能是空的。这时看板返回**空看板**，
`sources` 是空数组，前端显示「暂无可用的数据来源」。

**不报错，也不假装「用量为零」** —— 全是 0 的看板会被读成「这个月没生成过」，
而真相是「看板没接数据源」。这两件事必须分得开。

## 4. 权限

| 码 | 含义 |
|---|---|
| `page:usage` | 能不能**进这一页**（前端路由守卫 + 侧栏） |
| `usage:read` | 能不能**看自己的**用量 |
| `usage:read:all` | 能不能**看别人**的用量 |

- 页面码与接口码**分开**：关掉页面 → 接口自动失效（见 `docs/PERMISSION_PAGES.md`）。
- 「数据范围」是数据权限，不是页面入口 —— 所以 `usage:read:all` 不写进前端路由。
- **越权降级而不是报错**：没有 `usage:read:all` 却传 `scope=all`，后端把它降级成
  `mine` 并在响应的 `summary.scope` 里写回**实际生效**的范围。
- 界面必须跟着降级：没有 `usage:read:all` 时「全部成员」这一档**显示但禁用**
  （附一句原因）。显示着「全部成员」却只给一个人的数据，比直接不给看更糟。
- 内置角色：`editor` / `viewer` 都带 `usage:read` + `page:usage`；`usage:read:all`
  **不给**默认角色 —— 看别人的用量是管理视角，应由管理员显式授予。

## 5. 未来预留

| 想加的东西 | 预留在哪 | 动多大 |
|---|---|---|
| 新数据来源（音频 / 数字人 / 外部供应商） | `core/ports/usage_metrics.py` 的注入口 | 一个 provider 文件 + 一行注册 |
| 新构成维度（供应商 / 渠道 / 成本） | `UsageDimension` + `aggregate_rows` 的维度表 | 一个维度名 + 一行归一 |
| 模板 × 使用人关系 | `UsageRow.template_*` + `UsageAggregate.template_users` | 来源方填三个字段，看板自动合并 |
| 新时间粒度（小时 / 月） | `UsageGranularity` + `bucket_key` | 一个字面量 + 一个分支 |
| 成本 / 余额口径 | `UsageRow` 加字段（如 `cost`），汇总与构成各加一列 | 加字段，来源方自己填 |
| 导出 CSV | 新增 `GET /usage/export`（同权限、同区间口径） | 一个端点 |
| 环比 / 同比 | 前端拿两个区间的 overview 相减 | 纯前端 |
| 用量告警（阈值、配额） | 新增 `usage:quota` 权限码 + 一个 `limits` 模块 | 新模块 |
| 按人排行 | 现有的 `owner` 维度已经够，排序换一下即可 | 零 |

**预留的形状是「注入口 + 契约字段」，不是「空页面」。** 一个还没决定要不要做的
页面占位，等于逼着后来人猜它长什么样；而一个已经定好的接口位置，接上去就行。

## 6. 不做的事

- **不引图表库**：只需要一种图形，自绘更省、更贴主题。
- **不做实时刷新**：用量是回看性质的数据，按需刷新即可（react-query `staleTime` 60s）。
- **不在看板上提供写操作**：看板是只读页面。
- **不在前端重算口径**：`share`、`successRate` 都由后端算好，前端只画。
