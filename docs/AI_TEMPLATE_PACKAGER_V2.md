# AI 会话调用指南：按素材包用途封装视频模板

适用项目：雨范 AI 工作台。命令入口：`POST /api/v1/template-manifests`（预检 → 保存 → 发布）。
> 2026-11-14：离线脚本 `api/scripts/package_video_template.py` 已下线；下面的 `--check-server` /
> `--apply` 分别对应 `POST /template-manifests/validate` 与 `POST /template-manifests` + `/publish`。

## 约定

**封装 = 原视频 + 功能提示词 + 输入规则。产品、图片换场景各选一个已封装对象；多人换脸分别选择各人物卡；文字换场景只输入原片和可编辑描述，不选择素材包。**

## 新增：现有视频卡片的文字换场景

文字描述本身足以定义新场景时，使用 `kind: "scene"` 与 `scenePromptDefault`。不提供 `pack`、`packs`、参考图或 `scopeOptions`。原有“选择一个场景素材包”仍适用于有场景参考图的模板，两种功能可以挂在同一个原视频卡片。

会话可直接这样调用：

> 按本指南为现有视频卡片新增“文字换场景”。原片资产 ID 为 ac1d588d36294fa49c809d46bb1dbb6d。使用下面「文字换场景」一节的配置形状（示例文件已随离线打包器下线移除）。第一段酒店会客厅描述作为 scenePromptDefault，在工作台输入框预填并允许用户修改；其余提示词作为固定保留约束。只有原视频媒体，不选择场景包，不上传参考图。保留现有产品、人物和图片换场景功能，完成封装并返回入口，不提交生成。

完整酒店配置 和 固定约束提示词 已保存。配置里的 `video.assetId` 是本项目米兰之夜原片；用于其他视频时替换为实际原片 ID，并按该原片修改固定约束及封装 key。

```json
{
  "key": "my-scene-text-v1",
  "name": "视频卡片名称",
  "video": {"assetId": "实际原片ID"},
  "functions": [{
    "key": "scene-text",
    "name": "文字换场景",
    "kind": "scene",
    "scenePromptDefault": "将原视频场景替换为明亮雅致的高档酒店会客厅……",
    "prompt": "{{ScenePrompt}}\n\n保持原有人物、产品、动作与原音频。"
  }]
}
```

- `{{ScenePrompt}}` 必须恰好出现一次，运行时只替换这个参数，固定约束保留原文。无需为原视频强行补写 `{{Mixed 1}}`；如原文已有该引用则可保留。唯一媒体始终是 `Mixed 1` 原片。
- `scenePromptDefault` 为输入框默认值，非空、最多4000字、不含模板引用标记。用户可编辑并恢复默认。目录轮询不会重置用户输入。
- prepare 请求带 `videoTemplateId` 和 `scenePrompt`；`packId/packVersion` 为 null，`referenceIds` 为空。省略 `scenePrompt` 时使用模板默认值，显式空白会拒绝。该模式不接收散图、素材包、替换范围或补充要求。
- 完整提示词、当次场景描述与原片记录在任务快照，后续模板变化不会覆盖历史输入。修改描述会产生不同任务配置；同一请求 ID 不可复用于不同描述。
- 服务端需提供 `x-template-scene-text: 1` 能力。MVP `--check-server` 会检查契约；旧服务不支持时停止，不能退化成创建假场景包。

主要功能为替换人物、替换产品、替换场景。封装时声明提示词编号对应的用途；运行时用户从工作台选择同类型素材包，服务端按用途排列图片，完整附带该包其他参考图。

| 输入 | 产品替换示例 | 规则 |
|---|---|---|
| `{{Mixed 1}}` | 本例卡片原视频 | 视频编号以声明为准，也可以是 Mixed 4 |
| `{{Mixed 2}}` | 用户所选产品包的正面图 `front` | 按用途取图，固定第 2 位 |
| 其余图片 | 同包三视图、细节图、侧面图等 | 排在声明槽位后，沿用包内顺序，全部上传，无需在提示词中逐张引用 |

提示词只出现 `Mixed 1/2`，不代表只能上传两个输入。未点名图片也是有效参考；它们的 `inPrompt` 为 false，不影响上传。工具不会为辅助图片添加提示词引用，也不会自动改写用户原文。

换包时，只有声明的图片用途是模板必需项。例如只声明 `front` 的产品模板，从“正面+三视+细节”切换到“正面+侧面”仍可运行。找不到所需用途时停止，不用其他用途顶替。产品、场景多个参考槽位仍从同一个对象包取图；多人换脸每位人物的 `front` 则必须分别取自该位所选角色卡，同一卡的第二张正面图只能作为该人物的辅助图，不能顶替另一人。

**提示词原文和 Mixed 编号均保留。** 用途绑定模式要求编号从1连续声明且包含唯一一个 `source_video`，视频可以在任意位置；不再为了视频移到第1位而改写提示词。旧版没有 `bindings` 的 `mediaOrder` 模式仍沿用原片第1位。

## 用户可以直接这样说

> 按 docs/AI_TEMPLATE_PACKAGER_V2.md 封装模板。视频在 D:/素材/原片.mp4，提示词在 D:/素材/产品替换.txt。功能是“产品替换”。`{{Mixed 1}}` 是视频，`{{Mixed 2}}` 是运行时所选产品素材包的正面图。包内其余图片全部上传作为辅助参考，即使提示词未引用也不能遗漏。保留提示词原文，用户可以换产品包。视频默认私有，请预检后完成封装并返回工作台链接。

如果原片已归档，直接提供视频资产 ID 即可。用户提供了默认包 ID 就复用该已发布包；没有提供时，工具按名称、ID 排序，从授权目录选择第一个用途齐全的同类型已发布包作为默认示例，并在检查结果与报告中说明。运行时仍可换包，默认包不锁死模板。

同一视频需要三项功能时，分别提供三份提示词及编号用途声明。例如：人物替换 `Mixed 2=front`（人物正面身份图）；产品替换 `Mixed 2=front`（产品正面图）；场景替换 `Mixed 2=main`（场景主参考）。各功能使用对应类型素材包，不把一种类型的图片自动当成另一种类型。

多人换脸在工作台「选择目标人物」卡片区按出镜顺序多选，选中卡片的 1、2、3 表示第几位人物；再次点击可取消，后续序号前移，选满模板要求人数后才能准备。只有人物换脸支持这类多选，产品、场景继续选择一项。

三人模板可以直接这样调用：

> 按本指南封装三人换脸。保留提示词原文与编号，Mixed 1、2、3 分别对应第1、2、3位人物角色卡的正面身份图，Mixed 4 是原视频。运行时由用户在「选择目标人物」选择3张不同角色卡，各人物卡独立对应自己的提示词槽位，其他图片只补充该人物参考。不合并人物卡、不创建多人包，不提交生成。

复制 三人换脸配置 和 三人提示词示例 即可参照这个编号布局（示例文件已移除，形状见上文 manifest 结构）。封装时只需一个兼容的默认人物包作第1位样例，第2、3位显示待选择；不要求预先把三个人物放在同一个包里。

AI 执行时遵循以下步骤：

1. 读取本指南和已有封装配置，确定视频、功能类型、提示词原文及明确声明的编号用途。缺少用途声明才追问，不要求用户重复提供已有包中的每张图片。
2. 生成 JSON 配置。默认复用现有素材包；不要自动新建、改图、改用途或重新发布现有包。除非用户要求可选范围，不添加 `scopeOptions` 或 `ReplacementScope`。
3. 执行本地预检与 `--check-server`，核对所选默认包、权限和服务契约。若用户指定包，禁止悄悄换成别的包。
4. 在用户已要求封装的范围内执行 `--apply`。重复调用沿用同一 key、配置与进度文件；内容变化需要新版本时使用新 key，不删除进度绕过冲突。
5. 返回卡片入口、每项功能 ID、默认包及版本、编号用途、实际样例媒体清单和提示词摘要。封装命令不提交视频生成。

## 最小配置

可以复制 复用素材包示例 及 提示词示例，放入原片所在目录。下面使用已归档原片：

```json
{
  "key": "product-template-v2",
  "name": "米兰之夜",
  "video": {"assetId": "实际的原片资产ID"},
  "packs": [{"key": "product", "kind": "product"}],
  "functions": [{
    "key": "replace-product",
    "name": "产品替换",
    "pack": "product",
    "promptFile": "产品替换.txt",
    "bindings": {
      "{{Mixed 1}}": "source_video",
      "{{Mixed 2}}": "front"
    }
  }]
}
```

- 新视频用 `"video": {"file": "原片.mp4", "shared": false}`。`file` 和 `assetId` 二选一；后者不重新上传视频。复用已有视频不会自动改名、撤回分享。
- `packs` 是默认包选择声明。复用包只写 `key`、`kind`、可选 `packId`，无需 `references`、图片路径或产品包审核范围。`packId` 省略时自动选择；首次执行选择结果保存在进度中，重试时不悄悄更换。
- `kind` 为 `product/character/scene`。产品用途：`front/multiview/detail/back/side`；人物：`front/side/fullbody`；场景：`main/angle/detail`。
- `bindings` 从 Mixed 1 连续编号，唯一一个视频槽位的值为 `source_video`，其余为该类型图片用途；原片可以在 Mixed 4 等位置。提示词中每个 Mixed 引用都必须有声明；未引用辅助图不需要声明为必填。
- 人物模板声明几个 `front` 就分别选几张人物角色卡（最多6位）；多人模式只声明各自的 `front` 身份槽位，侧脸、全身等图由对应角色卡自动补齐。不同人物必须使用不同角色卡和独立身份图；产品、场景保持单包选择。
- 提示词只需提供 `prompt` 原文或 `promptFile` 文件其中一项。正文内部空格、标点、换行保留；首尾空白按 HTTP 契约统一清理，文件末尾换行不影响重复调用。包内附加图片不需要对应的提示词引用。
- 所有相对路径以配置文件目录为基准。JSON、提示词使用 UTF-8。key 使用字母、数字、下划线或连字符，最长40字符；包和功能的 key 各自唯一。
- 同一视频可封装多项功能，每项写一个 `functions` 条目。`pack` 引用 `packs` 的 key；名称相同的处理类型也可有多项功能。
- 只有需要用户选择范围时才配置 `scopeOptions`，并在提示词写 `{{ReplacementScope}}`。此时运行文案会替换该参数；普通固定提示词保持原文。
- 可选范围不等于用户授权范围：工作台默认不勾选，必须明确选择。切换产品或目录刷新只剔除已不支持的选项，不能自动全选或扩大范围；核对提示词使用当次实际选择。已准备任务保留历史快照，调整范围后需重新准备。
- 可选 `aspectRatio` 为 `9:16/16:9/1:1`，默认 `9:16`；可选 `duration` 为2–15秒整数。原片须为1–15秒、含音轨的完整MP4，最大300MB；媒体真实性由上传/归档接口探测。

## 命令和认证

在项目根目录执行：

```bash
# 预检：规则 + 素材存在性，不落库
curl -X POST http://127.0.0.1:8080/api/v1/template-manifests/validate \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d @manifest.json

# 保存配置（同 key 同指纹幂等）
curl -X POST http://127.0.0.1:8080/api/v1/template-manifests \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d @manifest.json

# 发布：投影素材包与视频模板（复用模式不会新建或发布素材包）
curl -X POST http://127.0.0.1:8080/api/v1/template-manifests/<key>/publish \
  -H "Authorization: Bearer $TOKEN"
```

认证用 `Authorization: Bearer $TOKEN`（令牌由已授权登录流程取得，只放环境变量）。只复用已有视频和包时，需要 `asset:read`、`template:read`、`template:pack:manage`；上传新视频另需 `asset:create`，主动分享另需 `asset:share`。复用已有包不要求参考素材维护或素材包发布权限。服务端仍逐请求检查授权。

令牌通过已授权登录流程取得，只放环境变量，不写配置、进度、报告、命令参数或聊天正文。工具不自动登录、不抓取浏览器登录态。

默认 API 为 `http://127.0.0.1:8080/api/v1`，可用 `--api-url` 修改。后端需加载本版代码；检查创建接口同时声明 `x-template-key-idempotency: 1`、`x-template-role-bindings: 2` 或更高版本。旧服务会在上传前停止并提示更新重启。

## 输出与重试

报告包含 `sourceId/sourceName`、每项功能的 `videoTemplateId`、默认 `packId/packName/packVersion`、`bindings`、`requiredPackCount`、`includeAllPackImages: true`、样例 `mediaOrder`、提示词原文 `promptSha256` 及 `workbenchPath`。工作台链接为相对路径，接在前端地址后打开。多人所需的角色卡数量会明确返回；只有选齐后才能准备。

`mediaOrder` 是创建时默认包的实际媒体清单；换包运行时按声明用途重排并完整附带新包图片，数量和未引用图的编号可以变化。最终当次输入以任务输入快照为准。

运行时人物按选择序号逐一对应提示词槽位，每个人物卡的其余图保留所属人物的说明并附带。所有对象卡的参考图合计最多10张（当前生成接口限制），超出时明确停止并要求选择更精简的卡，不会静默丢图或合并人物身份。

首包和额外人物包均冻结所选发布版本：工作台提交 `packId/packVersion` 与按序对应的 `extraPackIds/extraPackVersions`，后端以发布快照解析用途与文件，专员尚未发布的编辑不会污染当前选择。任务快照记录各包 ID、版本与逐图用途；提交前再次校验每张角色卡是否仍可用。兼容旧调用省略额外版本时，服务端解析当时版本并记录。

默认进度保存在 `api/var/template-packager/`（由 `TEMPLATE_PACKAGER_STATE_DIR` 决定，多机共用时指向共享盘），可用 `--state` 指定。状态绑定服务地址、账号和配置内容；模板稳定键按账号、封装 key、功能 key 派生。中断后原样重跑，同键同配置复用结果，同键异配置拒绝。未完成步骤之前的上传或模板创建会保留，不自动删除。

视频默认私有。`shared: true` 才主动分享；false 不撤回已有分享。卡片标题沿用归档原片名称，配置 `name` 用于各功能模板名称前缀。

现有模板目录仍是 JSON + 进程内锁，只承诺单后端进程防重。并发会话使用同一进度文件；异常退出遗留 `.lock` 时先确认旧进程已结束再清理。若丢失进度，自动默认包选择可能变化；需要固定默认包时显式保存 `packId`，不要把自动选择当成长期包绑定。

如果确实需要从本地散图维护并发布新素材包，可使用 [兼容流程](AI_TEMPLATE_PACKAGER.md)；新封装仍建议使用 `bindings`。旧版 `mediaOrder` 配置继续兼容，其严格的完整用途依赖保持原样，不自动改动历史卡片。
