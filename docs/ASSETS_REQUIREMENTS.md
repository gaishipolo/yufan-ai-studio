# Assets 页面需求梳理

日期：2026-11-06（Asia/Singapore）  
对象：`/assets`「素材资产库」  
文档用途：需求基线与实现索引。初次梳理时只输出文档；用户确认 T01–T07 后已开发，交付与验证见 `ASSETS_INTEGRATION_PLAN.md` 第 11 节。  
基线说明：第 2–10 节主要记录初次静态检查及建议；第 11、12 节收敛业务规则。后续确认范围、实际实现和剩余未验证项以开发目标确认单的实施记录为准。

## 1. 页面定位与用户价值

需求已更新：素材库分为「公共素材」和「我的素材」。专员维护公共替换对象；普通用户可上传和管理个人原片，并主动分享单条原片供他人调用。产品 / 人物 / 场景仍只能调用专员封装的对象。下文个人归档规则保留为当前实现基线；目标以第 11、12 节为准。

目标定位为「公共可用素材与个人原片的管理入口」：普通用户查找公共对象、管理自己的原片，专员维护封装内容；生成结果仍按任务归属读取。

| 用户 / 场景 | 需要完成的动作 | 价值与完成标准 |
| --- | --- | --- |
| 有素材创建权限的创作者 | 将本机文件或 inbox 文件登记为原片、人物、产品、场景、音频 | 文件与索引已保存，归属正确，刷新后仍能找到；明确知道每个文件是否成功 |
| 有素材读取权限的使用者 | 找到素材，核对内容和规格，下载原件 | 预览可用或有明确替代操作；下载得到原始文件 |
| 使用替换模板的创作者 | 确认素材是否适合替换流程，再进入模板页 | 区分「已归档」和「满足生成条件」；上传单张图片不等于发布了素材包 |
| 有模板读取权限的使用者 | 查看已保存的替换任务结果，定位调用档案 | 能区分产物保存与人工验收；可预览、下载并追溯任务 |

首次价值时刻：第一次上传或登记后，看见对应素材卡片，能打开核对并下载，刷新后仍存在。页面显示成功提示本身不构成完成。

最短流程：选择分类 → 上传文件 / 登记 inbox 相对路径 → 确认逐条归档结果 → 找到并预览素材 → 下载原件或前往模板使用。生成与人工评价仍由模板流程负责。

## 3. 已有实现

### 3.1 页面与输入

- `/assets` 的路由、侧栏和首页卡片均要求 `asset:read`。
- 默认进入「原片」，可切换人物、产品、场景、音频；分类保存在 URL 的 `category` 参数，非法值回退原片。页面没有「全部」入口，归档接口支持 `all`。
- 上传与 inbox 登记入口受 `asset:create` 控制；后端亦校验创建权限。
- 文件选择支持多选，按选择顺序串行上传；遇首个失败即结束循环，后续文件不再上传。单个请求进行时上传按钮显示加载并禁用。
- inbox 登记接受相对路径，按当前分类复制文件，保留 inbox 原件；后端阻止路径越界。
- 前后端支持原片 MP4、图片 JPG/JPEG/PNG/WebP、音频 MP3/WAV；后端检查文件可解析性、分类匹配及非空，单文件上限为 `300 × 1024 × 1024` 字节，错误文案称「300MB」。

### 3.2 浏览、保存与权限

- 卡片展示名称、大小、时长或尺寸；可打开弹窗查看媒体、归档相对位置与 SHA-256，并下载原件。
- 当前素材弹窗把 `asset.url` 传给媒体组件，视频读取 `/file` 原始文件；播放器已有视频解码错误提示和原件下载。
- 归档列表按创建时间倒序；返回 `root / items / total / usedBytes`。`total` 与 `usedBytes` 只统计当前用户、当前分类的索引记录，不是整个 Z 盘容量或剩余空间。
- 原件保存到 `library/<category>/YYYY/MM/`，索引保存在 `catalog/assets/*.json`，含归属、媒体信息、路径与 SHA-256；归档盘不可用时直接报错，不回退保存到其他磁盘。
- 列表与文件访问均按本人归属控制；素材模块刻意没有 `asset:read:all`。管理员身份不自动等于可读取别人的素材。
- 查询缓存键含当前用户，上传或登记成功后使其素材列表缓存失效。

### 3.3 生成结果与上下游

- 本页下方展示替换任务目录中带 `outputUrl` 的记录，可预览与下载；不是所有模块的统一生成结果库。
- 结果来自模板接口，要求 `template:read`，按任务本人归属返回。页面已有「生成完成后仍需人工验收」的说明，但本区未显示逐条人工验收结论。
- 后端已有视频 `/stream` 兼容预览接口，派生文件与原件分开；生成失败时实现会回退原视频，因此不能承诺所有预览都可播放。
- 模板页已有已发布素材包选择；素材包配置来自 `catalog/packs`。当前 Assets 页没有封装、编辑或发布素材包的入口。
- 替换任务已有输入快照、任务状态与独立人工评价能力；本页梳理不要求重建这套能力。

## 4. 已知缺口与文档差异

| 编号 | 事实 / 差异 | 用户影响 | 建议优先级 |
| --- | --- | --- | --- |
| G01 | 主列表错误只显示文本，无就地重试；刷新错误分支遮住缓存列表 | 短暂失败后看不到旧内容，也不清楚如何恢复 | P0 |
| G02 | 无数据时统计使用 `0` 和 `0 B`，根路径使用默认字符串 | 加载或失败被误读为零素材，默认路径像已确认的连接状态 | P0 |
| G03 | 批量上传只有整体 toast，无逐条进度与结果；首错后未处理文件未说明 | 不知道哪些已保存，重传可能产生重复归档 | P0 |
| G04 | 上传与登记可同时发起，分类可随时切换；缺少批次级互斥与固定分类摘要 | 当前视图可能与在途请求的分类不同，容易误解归档位置 | P0 |
| G05 | 生成结果区只取 `data`，未处理加载、错误和模板读取权限 | 加载中或 403/网络失败可能显示「暂无已下载的生成结果」 | P0 |
| G06 | 缩略图忽略请求错误，图片解码失败也没有恢复入口；音频/图片主预览缺少对应加载后错误反馈 | 可能持续显示「加载预览…」或破图 | P0 |
| G07 | 后端支持兼容视频预览，本页素材弹窗仍读取原视频 | HEVC / 10-bit 等视频可能归档成功却无法在浏览器播放 | P0 |
| G08 | 页面声称原片要求带音轨的 1–15 秒 MP4，但归档阶段只校验合法媒体与分类；时长和音轨门禁在模板准备阶段 | 用户将「归档成功」理解为「可直接生成」 | P0 |
| G09 | 本页无搜索、分页、排序控件；归档接口无关键词、分页、分面统计字段 | 素材增加后难以查找，全量读取与缩略图请求成本上升 | P1 |
| G10 | 上传图片只能成为散素材，缺少封装为模板可用素材包的页面流程 | 新用户完成上传仍可能无法在模板页选择目标包 | 待确认范围，建议 P1 独立迭代 |
| G11 | 当前结果卡片主要显示目标名称和磁盘路径，无任务时间、生成/验收状态及任务跳转 | 难以辨认多次生成和判断是否已认可 | P1 |
| G12 | 每次登记生成新 ID，常规上传 / inbox 登记没有内容去重或幂等请求标识 | 超时后重试、重复选择文件可能增加副本 | P0 定义恢复规则；接口增强 P1 |

特别区分以下两套能力：

1. `GET /assets` 查询数据库素材，已有类型分面与关键词；当前页面实际调用 `GET /assets/archive` 的文件索引归档链路。前者的搜索统计不能直接算成本页已有能力，也不能混用两种 ID。
2. 通用素材删除、详情、上传凭证接口标记为待实现；`asset:delete` 权限存在不代表删除可用。归档上传和本页弹窗已可用，不应因通用接口占位而判断为全部未实现。
3. `REPLACEMENT_TEMPLATES.md` 写有「分类与搜索存入 URL」，本页只有分类，没有搜索；该描述不能作为本页搜索已完成的依据。
4. 同文档称视频派生预览为 360p、路径不带版本；当前代码使用 `hd-v2`，视频最长边限制 1920 且不放大小视频，文件名带版本。后续实施时应同步更新旧说明，本轮不修改该文档。

## 5. 建议需求范围

本节保留基础归档需求。涉及封装角色、发布范围、普通用户入口和个人管理的建议，已按最新要求由第 11、12 节替换；专员封装、个人原片管理及分享、模板授权调用现属于核心范围。

### 5.1 必须有：补齐已有归档闭环（P0）

| 编号 | 目标行为 | 输入 / 输出与完成条件 |
| --- | --- | --- |
| R01 | 列表、统计、结果区分别处理加载、空、错误、成功刷新 | 只有请求成功才显示零；有缓存时保留旧内容并标记更新失败；就地重试可恢复 |
| R02 | 多文件上传使用批次级状态，逐条保留结果 | 保存批次分类与文件清单；区分等待、处理中、成功、明确失败、结果未知、尚未处理；成功项不重复提交 |
| R03 | 上传和登记反馈留在当前操作区域 | 显示文件名、分类、结果与下一步，toast 仅作补充；在整个批次结束前禁用重复提交和并发登记，锁定操作分类 |
| R04 | 预览可靠降级，下载始终对应原件 | 视频播放使用兼容派生预览，原件独立下载；图片、音频、缩略图失败可识别并安全重试；派生失败不标成归档丢失 |
| R05 | 明确归档条件与生成条件 | 建议保留合法 MP4 的归档能力，显示「可用于替换」或具体不适用原因；模板继续执行 1–15 秒、有音轨门禁，不裁剪、不伪造音轨 |
| R06 | 结果区按模板权限呈现，并区分保存与人工验收 | 无 `template:read` 时不请求模板目录，显示权限说明；有权限时只在成功读取且无记录时显示空态；生成成功不写成验收通过 |
| R07 | 明确重复与未知结果的恢复策略 | 明确失败项可单项重试；超时或断连且服务端结果不明时先刷新核对；未确认前禁用该项直接重传，说明可能已归档 |

R02 建议沿用串行、首错暂停的策略：保留已成功项，失败或未知项明确标记，后续项为「尚未处理」。明确失败时可重试该项或跳过后继续；结果未知时先核对，再决定续传。当前无幂等标识，不能承诺超时重试绝不重复。

R05 是产品建议而非现有事实的变更记录。若后续选择「原片分类只接受可用于替换的素材」，则需同时调整上传、inbox 登记、历史素材提示和后端校验；不应只在文件选择器拦截。

### 5.2 应该有：查找与使用衔接（P1）

- 名称搜索写入 URL，去首尾空白，大小写不敏感；分类与关键词共同生效，清空搜索保留分类。可先在已成功取回的当前分类中筛选，但必须标明范围。
- 统计分别标注「匹配 N 项」「当前分类 N 项 / 索引原件合计大小」；不称为磁盘总占用，不包含派生预览、输入快照、生成成片及 inbox。
- 素材详情补齐分类、创建时间、格式、尺寸、时长、音轨和生成适用性；未知值显示「未知」，不显示 `0×0`。路径、哈希放在可展开的归档信息中。
- 提供「前往替换模板」入口；如需携带素材选择，另定义路由参数与模板接收校验。音频目前不属于三类替换模板的直接目标，不为其承诺生成入口。
- 结果卡片显示任务标识、创建时间、生成状态、人工评价状态和对应任务入口；复用已有任务事实，不在本页新增第二套评价状态。
- 明确散图与已发布素材包的差别；近期可先给出发布途径说明。现已明确由专员封装发布、普通用户调用，属于打通核心范围，见第 11 节。
- 分页、服务端搜索和分面统计按真实素材规模与加载成本决定；实施分页前同步契约，不能用分页内条数冒充总量。

### 5.3 以后再做 / 本轮不默认纳入

删除或回收站、重命名和移动分类、标签收藏、批量下载、通用原件共享与团队协作编辑、存储配额和分析、跨模块统一产物库、断点续传及自动内容去重。

这些能力不是现有归档闭环的必要前置条件。保留已有多文件选择、归属校验、权限、输入快照与原件下载；不以 MVP 为由删除。删除若后续立项，需先定义素材包与历史调用引用规则及文件清理边界。

## 6. 建议页面结构

从上到下：页面标题与价值说明 → 分类和查找工具 → 当前范围统计 → 上传入口及逐条反馈 → 素材卡片列表 → 生成结果归档。

inbox 登记作为「登记已有文件」次级入口，说明先放入 inbox、仅填相对路径、原件保留。完整磁盘根路径放在归档信息中，不作为已连接的凭证。没有创建权限的用户不展示要求其上传的空态操作。

素材弹窗集中展示预览、主要规格、适用性、原件下载；文件路径与 SHA-256 为辅助核对信息。预览和原件下载应各自有状态，预览失败时仍能尝试读取原件。

## 7. 页面状态契约（目标，尚未实现）

| 区域 / 状态 | 精确触发条件 | 内容或文案 | 操作、禁用与恢复 |
| --- | --- | --- | --- |
| 列表首次加载 | 当前分类首次请求，无缓存且 pending | 「正在读取素材…」；统计为 `—` | 显示占位，不出现空态；返回成功或错误后退出 |
| 分类空 | 请求成功，当前分类素材为零，无关键词 | 「暂无原片 / 人物等素材」 | 有创建权限提供上传 / 登记；无权限提示联系素材维护人员 |
| 搜索空（P1） | 请求成功，关键词非空且匹配为零 | 「没有找到匹配的素材」 | 清空搜索；不提示创建第一条素材 |
| 列表正常 | 请求成功且有匹配项 | 卡片与真实范围统计 | 可查看、下载；后台刷新不清空列表 |
| 列表首次错误 | 请求失败，当前分类无缓存 | 「素材读取失败」及可理解原因；统计 `—` | 提供「重试」；归档盘错误提示检查连接，不显示首次空态 |
| 后台刷新 | 已有缓存且正在重新请求 | 保留列表与上次统计，轻量更新提示 | 读取结束后替换数据；不把旧统计当实时磁盘状态 |
| 刷新错误 | 请求失败但有缓存 | 「更新失败，以下为上次加载的素材」 | 保留内容，提供重试；不显示成功更新 |
| 上传处理中 | 批次已建立且仍有请求在途 | 「正在归档第 X / N 个：文件名」与逐条状态 | 上传、登记与分类切换禁用至批次暂停或结束；不用虚构的百分比 |
| 批次成功 | 所有条目均返回归档成功 | 「N 个文件已归档到〔分类〕」 | 刷新对应分类；若列表刷新失败，分别显示归档成功和列表更新失败 |
| 批次部分失败 | 某项明确失败，循环暂停 | 「已成功 X 个，失败 1 个，尚未处理 Y 个」 | 保留列表，修正后仅重试失败项，或跳过后继续；成功项不重传 |
| 上传结果未知 | 连接中断 / 超时，无法确定是否已登记 | 「此文件归档结果待核对」 | 先刷新并核对；未核实前不提供直接重传，不能将其标为未处理 |
| inbox 登记中 | 表单合法且请求进行中 | 「正在登记并复制文件…」 | 禁止重复登记和并发上传；成功才清空输入，失败保留路径 |
| inbox 登记错误 | 路径越界、文件不存在、不合规或存储错误 | 输入区域显示具体原因 | 修改路径或恢复连接；结果未知同上传核对规则 |
| 缩略图错误 | 缩略图请求或解码失败 | 类型占位和「预览不可用」 | 不无限显示加载；可重试、打开详情 |
| 主预览加载 / 错误 | 媒体读取中 / 请求或解码失败 | 弹窗内显示读取状态或具体失败 | 可重试；原件下载独立可用时保留；不把派生文件作为原件下载 |
| 未选素材 | 未打开详情或已关闭 | 展示素材列表 | 不显示「缺少素材」；所选记录不再存在时关闭详情并说明 |
| 结果无权限 | 当前用户无 `template:read` | 「当前账号无权限查看生成结果」 | 不请求模板目录；不影响素材区操作 |
| 结果加载 / 错误 / 空 | 独立请求 pending / 失败 / 成功且无 `outputUrl` 项 | 分别显示加载、错误、暂无已归档结果 | 错误提供就地重试；刷新失败保留旧结果，空态不用于错误 |
| 结果正常 | 返回带 `outputUrl` 的记录 | 「已归档成片」及真实人工评价状态 | 文件存在性仍以读取结果为准；缺失给错误，不冒充可播放或已验收 |

键盘可操作全部按钮；弹窗打开与关闭管理焦点；加载与成功反馈使用可访问状态语义，错误使用警报语义；动画遵循减少动态效果偏好。以上为目标验收条件，不代表本轮验证了所有现有基础组件。

## 11. 素材库与模板库打通方案（按角色分工修订）

### 11.1 已明确的业务规则

用户要求：素材库由具有专员权限的人员维护和封装；封装后普通用户可以调用；普通用户只能选择已封装的产品 / 人物 / 场景进行替换任务。

目标链路：**专员上传整理 → 封装草稿 → 发布可调用对象 → 普通用户选择 → 准备输入快照 → 确认执行**。

共享的是已发布对象的受控使用权，私人原件列表与其他人的任务历史继续隔离。上一版「仅本人可调用包」不符合该目标，本节替换原方案。此处为目标设计，尚未实现。

### 11.2 角色与页面职责

| 能力 | 素材专员 | 普通任务用户 |
| --- | --- | --- |
| 上传整理原始人物 / 产品 / 场景素材 | 有素材维护权限时可用 | 无此维护入口 |
| 创建、保存、编辑封装草稿 | 有封装权限时可用 | 不可用 |
| 发布、停用对象 | 有发布权限时可用 | 不可用 |
| 模板中选择已发布对象 | 有模板调用权限时可用 | 可用，仅限发布给本人可用范围的对象 |
| 修改包内图片、主图、固定描述与封装参数 | 编辑新版本并发布 | 不可用 |
| 配置替换范围、任务备注 | 按模板授权 | 按模板授权，不能覆盖包固定属性 |
| 准备与执行任务、查看结果 | 按模板权限与任务归属 | 按模板权限与任务归属 |

专员是被显式授予能力的角色，不等于所有管理员或所有具备上传权限的人。素材库管理视图面向专员，包含原始素材、封装草稿、已发布对象。普通用户在模板库看到「选产品 / 选人物 / 选场景」卡片，不需要管理参考图集合。

普通用户可查看名称、主图、简要说明和必要的受控预览；默认不提供专员原件目录、磁盘路径、任意原件下载或封装编辑。核对任务输入时读取普通用户自己任务内的授权快照。

原片是独立输入：用户已明确普通用户可以上传、管理个人原片，并主动分享单条原片供他人调用，具体见第 12 节。这不授予普通用户封装人物 / 产品 / 场景的权限。

### 11.3 数据与发布规则

| 对象 | 职责与关联 |
| --- | --- |
| Asset 原始素材 | 保存原件、媒体信息、维护归属和哈希；能调用包不等于能任意读取其中所有资产 |
| PackDraft 封装草稿 | 名称、类型、1–10 张同类图片 ID、主图、描述及固定参数；仅有管理权限人员可见，一张图也可以封装 |
| PublishedPack 发布版本 | 固定引用与配置，记录版本、发布人、发布时间、状态、发布范围；发布前验证原件可读与哈希 |
| Run 调用记录 | owner 是实际创建任务的用户；记录包版本，准备时保存图片、配置、提示词和哈希快照 |

建议生命周期为「草稿 → 已发布 → 已停用」。已发布内容不可原地覆盖，修改产生新版本；旧版本可追溯不等于仍允许新任务调用。准备时解析、校验与快照必须使用同一发布版本。

用户已明确公共素材供所有用户共用。首期按当前工作台内所有具有对应读取 / 调用权限的用户开放；这里的公共不是互联网匿名访问。组织 / 项目细分范围不作为首期前置条件。专员未发布草稿不属于公共内容。

### 11.4 操作流程

专员流程：上传或登记素材 → 选择同一目标的图片 → 保存草稿 → 填名称、主图、描述与固定参数 → 校验发布。图片分类、ID 唯一性、封面归属、原件存在性、哈希和管理范围均由后端校验。发布失败保留草稿，在当前操作区域显示原因。

普通用户流程：选择替换类型和原片 → 选择已发布的产品 / 人物 / 场景 → 设置模板允许的任务参数 → 准备并核对实际输入 → 确认执行。普通用户不能从散图创建临时包，不能上传参考图替代已发布对象，不能修改封装参数。

最小价值闭环：专员 A 发布产品后，普通用户 B 不需要上传参考图，也不需要读取 A 的私人素材库，就能选择该产品并准备自己的替换任务。

### 11.5 需要调整的实现

| 当前基线 / 缺口 | 目标行为 |
| --- | --- |
| `packs(owner)` 仅返回本人维护的包 | 分离管理查询与可调用查询，后者按发布状态、范围和调用权限返回，不能按维护人与调用者相同过滤 |
| 前端通过调用者个人素材列表检查包是否缺图、读取封面 | 可调用目录返回服务端验证的可用性和受控封面 URL；个人素材列表仅用于本人原片，不作为专员包完整性依据 |
| `repo.media(id, owner)` 要求素材属于任务用户 | 原片允许本人拥有或当前有效分享；参考图经已授权发布版本的固定引用读取。两条授权路径分开，不能全局删除 owner 检查 |
| 准备契约允许无 packId 的散图模式 | 普通用户必须选有效的已发布包及版本；无包、未发布、越权或停用均拒绝；后端解析真实 referenceIds 和固定配置 |
| 仅隐藏手动选图入口不能阻止直接请求 | 服务端禁止普通用户以任意 referenceIds、名称或固定参数绕过封装规则；旧接口兼容也不能留下散图通道 |
| 封装与任务调用权限未分离 | 建议新增 `template:pack:manage`、`template:pack:publish`；调用复用模板读取 / 使用权限并检查发布范围，普通用户不授予封装权限 |
| 当前准备统一要求 asset:read | 区分本人原片、已分享原片与包调用授权；不要求调用者获得他人私人素材库权限，也不通过全局 asset:read:all 解决 |
| 私人原件端点只能按本人读取 | 保持该隔离，新增受控包封面 / 预览入口；仅允许读取授权发布对象中的展示内容，不接受任意路径 |
| 只有缓存目录校验不足 | 准备时重查发布版本、状态、范围与文件；执行前重查调用资格，缓存不能绕过停用 |

接口建议（尚未存在）：管理端提供草稿创建 / 更新、发布和停用；调用端提供已发布可用对象列表与受控预览。可采用 `/templates/replacement-packs` 管理路由及其 `/available` 查询；现有 replacement-catalog 可以聚合可调用对象，但必须改变原有本人包过滤。

准备请求以 `requestId / kind / sourceId / packId / packVersion / 模板允许的任务参数` 为主；固定参考图、名称和封装参数由后端解析。切换版本需明确提示，不能悄悄使用与用户所选不同的内容。旧格式散图请求应拒绝并提示升级；契约、前端类型和 OpenAPI 同步调整。

复用现有归档存储和共享媒体类型，不让业务模块互相直接 import 服务；各业务层保留权限判断。任务准备通过授权发布记录定位参考图，不以放开原始素材列表代替授权。

### 11.6 状态、停用与历史兼容

| 场景 | 目标行为 |
| --- | --- |
| 草稿尚未发布 | 仅专员可见，普通用户无法通过目录、ID 或预览读取；未完成配置可存草稿但不能发布 |
| 首次加载、读取失败、后台更新 | 加载、错误和空分开；有缓存保留内容；失败可重试，准备时仍校验权威状态 |
| 普通用户无可用对象 | 提示「暂无可用的产品 / 人物 / 场景，请联系素材专员」，不提供自行创建包或上传散图替代入口 |
| 未选择 / 搜索无匹配 | 分别提示选择 / 清空筛选；未选择禁用准备 |
| 包缺图、哈希变化 | 阻止准备并提示维护；只有预览失败时允许重试预览，不据此判定原件丢失 |
| 发布中、明确失败、结果未知 | 禁止重复发布；失败保留草稿；结果未知以同一请求标识核对，避免重复发布版本 |
| 越权或手工提交草稿、停用包 ID | 服务端拒绝，不能经 URL、referenceIds 或原件端点绕过 |
| 停用或收回发布范围 | 建议阻止新准备和未提交上游的执行；保留历史快照，提示重选；已提交任务继续查询及结果归档，不承诺撤销上游 |
| 发布新版本 | 新任务按所选版本校验，旧任务输入快照不变；执行时仍检查所引用版本的可调用资格 |
| 已生成的历史任务 | 按任务归属与既有权限查看其结果和输入；包后续停用不删除历史文件 |

历史包必须显式确认发布范围，不能把现有私人包或散图批量自动公开。素材维护归属、任务归属和历史快照保持不变。权限目录、角色授予与迁移说明需同步，既有角色不自动获得专员权限。

### 11.7 实施顺序与验收

1. 定义发布数据、版本、范围和角色权限，完成旧数据兼容策略。
2. 完成专员素材库的封装草稿、校验、发布、停用；普通用户无管理能力。
3. 完成模板可调用对象目录、受控预览、服务端包解析与任务快照，保留多原片批量反馈及零积分执行规则。
4. 补齐缓存刷新、停用反馈、重复请求恢复和关键权限测试。

验收必须使用不同账号：专员 A、普通用户 B，以及不在发布范围的用户 C。

- A 的草稿 B 不可见；发布给 B 可用范围后，B 可调用。
- B 没有 A 私人素材权限仍可通过发布包准备任务，快照含完整参考图；直接读取 A 的私人原件仍被拒绝。
- B 不能创建、编辑、发布或停用包；不能无包调用、伪造图片引用或改写包固定参数。
- C 知道包 ID 也无法调用或读取其受控预览。
- 包停用后新的准备和未提交执行被阻止，历史快照与结果保留，已提交上游的任务仍可查询归档。
- 新版本不改变旧任务输入，重复发布请求不产生多个相同版本；缺图和哈希变化不能报准备成功。
- 准备不提交上游生成，执行保留零积分门禁、防重复提交与提交结果未知保护。

上述两项已由用户补充明确：公共素材全员共用，普通用户允许上传原片，并可主动分享单条原片。最新个人管理和原片分享方案见第 12 节。

本次仅核对包归属过滤、参考图读取、前端完整性检查与权限边界，并修订本文档；未修改业务代码，未运行应用、测试或真实生成，目标方案尚未实施。


## 12. 公共素材、个人管理与原片分享（最新需求）

### 12.1 已确认规则与范围

用户已明确：普通用户可以上传原片；素材库有公共与个人两个分类；个人素材有分享按钮，分享后其他人可调用这一条原片；需要个人素材管理。

这两个分类是一级可见范围，不取代原片 / 产品 / 人物 / 场景的业务类型。目标结构如下：

| 一级入口 | 内容 | 谁维护 | 谁可调用 |
| --- | --- | --- | --- |
| 公共素材 · 产品 / 人物 / 场景 | 专员封装并发布的对象 | 有封装 / 发布权限的专员 | 工作台内有相应调用权限的用户 |
| 公共素材 · 原片 | 专员公开的原片，以及普通用户主动分享的原片 | 原上传者管理个人分享；专员管理其公共原片 | 工作台内有相应调用权限的用户 |
| 我的素材 | 当前用户上传的原片，包括私有和已分享 | 当前用户本人 | 私有时仅本人；分享期间他人也可调用 |
| 专员维护入口 | 原始参考图、未发布草稿、包配置 | 有相应权限的专员 | 草稿不对普通用户开放 |

素材库对普通用户提供「公共素材 / 我的素材」两个入口；专员可在公共素材上下文进入维护模式或管理入口，普通用户没有维护入口。专员上传并不自动等于已发布；参考散图和封装草稿不能混入普通用户的可调用对象目录。

个人原片分享后仍属于上传者，在「我的素材」显示已分享，同时在「公共素材 · 原片」中可被他人发现。两处展示同一素材，不复制文件、不转移归属。生成结果和调用档案继续按任务归属展示，不因分享原片而公开。

### 12.2 我的素材管理（建议首期范围）

| 功能 | 行为与边界 |
| --- | --- |
| 上传原片 | 默认私有；归档成功后显示本人卡片；生成适用性独立判断，不自动分享 |
| 浏览、搜索与筛选 | 查看本人的素材；按名称搜索，筛选全部 / 私有 / 已分享；卡片显示大小、时长、音轨、创建时间、适用性和分享状态 |
| 查看、下载、使用 | 本人可预览、下载原件、带入模板；模板已有多原片选择保留 |
| 重命名 | 建议仅改展示名称，不改原文件、ID、哈希或历史任务快照；失败保留原名称 |
| 分享 | 本人对单条原片点击「分享至公共素材」；成功后显示已分享及取消分享入口，不分享整个个人库 |
| 取消分享 | 建议本人可收回后续公共调用权；成功后公共列表移除，个人区仍保留 |
| 移除 | 建议首期采用逻辑删除 / 回收站；先撤下分享再移入回收站，排除新调用；存在进行中引用时按明确规则阻止或延后，不能直接删除依赖文件 |

以上管理操作中，上传与单条分享是用户明确要求；搜索、重命名、取消分享与回收站是为个人管理提出的具体建议，尚未实现。首期不默认加入批量分享、自动分享或永久物理删除。

对别人分享的原片，普通用户获得预览与任务调用能力，不能改名、修改归属、删除、替对方取消分享或直接再次发布同一记录。分享不自动授予独立的原件下载 / 导出功能；如需支持他人下载，应另定义产品规则。任务准备允许服务端读取原始文件并保存该次输入快照，详情需要明确这一事实。

### 12.3 模板库如何选择

1. 选择原片时提供「公共原片 / 我的原片」切换、搜索、预览和多选；使用稳定 ID 去重，自己已分享的原片不重复加入同一批任务。
2. 快速上传仍进入「我的素材」，默认私有；用户可先生成，是否分享由其主动操作决定。
3. 选择替换目标时，只展示专员发布的产品 / 人物 / 场景，普通用户不能使用自己的散图或分享原片替代目标包。
4. 准备时校验原片「本人拥有，或分享当前有效」，并独立校验目标包发布状态与调用资格。
5. 准备成功后，原片、目标包配置、提示词一起固定到调用者自己的任务档案；共享原片的上传者看不到其他用户的任务配置或结果。

价值闭环：用户 A 上传原片，默认只有 A 能用；A 主动分享后，用户 B 在公共原片中找到它，选择专员封装的产品并准备替换任务。B 无需访问 A 的私人列表，也无需重新上传原片。

### 12.4 数据、接口和权限影响

建议原片记录保留 `ownerId`，增加明确的可见性 / 分享状态、分享时间、状态版本及逻辑删除信息；`sourceOrigin` 可区分专员公共原片与用户分享原片。具体字段名是设计建议，不是当前契约。

公共目录合并展示符合条件的专员公共内容和用户有效分享记录；私有查询始终按本人归属。两者都需要明确分页、稳定排序、关键词与计数口径，不能先全量返回私人记录再由前端过滤。公共素材统计不等于任何个人存储占用，双入口引用不能重复计算同一物理文件。

| 能力 | 接口 / 授权建议（尚未实现） |
| --- | --- |
| 本人原片列表 | 复用或扩展归档查询，加显式范围参数；只返回本人记录 |
| 公共原片列表 | 新增受控的公共原片查询；只包含有效公开且未删除的记录，详情字段不暴露内部路径 |
| 分享 / 取消分享 | 原片 ID 下的分享状态接口，由后端核对 owner、业务类型和状态版本；重复设置同状态安全返回 |
| 名称修改 / 逻辑删除 | 独立管理操作，检查本人归属与引用规则；现有通用删除占位接口不能算作已支持 |
| 公共预览与生成读取 | 独立检查分享有效性；不直接开放全部归档 `/file`，不以可猜测 ID 代替授权 |
| 缓存 | 查询键包含账号、公共 / 个人范围和筛选条件；分享后刷新本人的两类查询，其他用户重新读取时可见，不承诺实时推送 |

普通用户可以分享自己的原片，不因此获得专员封装发布权限。若增加 `asset:share` 等权限点，应在普通任务用户的角色配置中显式授予并提供既有账号迁移说明，不能仅加入权限目录导致现有用户无入口。

后端对原片采用统一的「本人拥有或有效公开」调用判定，供列表、详情、预览、准备和执行使用；对改名、分享、取消分享、删除则始终要求管理归属。发布包的引用读取继续使用独立的包授权路径。

分享与取消分享需要有明确的并发先后：建议使用状态版本及资源级串行化，使取消分享与任务准备 / 执行的最终授权决定可判定，不能只在前端读状态后就默认成功。重试复用同一操作标识或期望版本；冲突时刷新事实并保留用户选择。

### 12.5 状态与撤回规则（建议）

| 场景 | 文案 / 行为 | 禁用与恢复 |
| --- | --- | --- |
| 我的素材首次为空 | 「还没有原片，上传第一条原片」 | 提供上传；公共为空不能复用此提示 |
| 公共原片成功读取且为空 | 「暂无公共原片，可使用我的原片」 | 可切换个人区；不把请求错误当为空 |
| 搜索无匹配 | 「没有找到匹配的原片」 | 可清空搜索 |
| 上传完成 | 「原片已保存，仅自己可见」 | 允许使用或主动分享；不显示已分享 |
| 分享中 / 取消分享中 | 当前卡片显示处理中 | 禁止同一素材重复变更；其他素材可继续操作 |
| 分享成功 | 「已分享，其他用户可在公共原片中调用」 | 更新个人与公共视图；公共列表刷新失败单独提示 |
| 明确失败 / 结果未知 | 卡片内显示原因；未知显示「分享状态待核对」 | 保留素材和草稿；未知先读取权威状态，不盲目反转操作 |
| 已选原片被取消分享 / 移除 | 「该原片已停止共享，请重新选择」 | 他人不能继续新准备或未提交执行；本人仍可使用未删除原片 |
| 名称修改失败 / 移除冲突 | 管理弹窗内显示具体原因 | 不伪报成功；保留名称草稿或原记录，说明引用约束 |

建议取消分享只阻止撤回之后的新调用以及尚未提交上游的执行；已经生成的结果和任务输入快照保留，已经提交上游的任务继续查询归档。不能承诺撤回所有已被合法使用的副本，尤其是当次任务快照。分享按钮旁应以简短说明明确该规则。

删除与取消分享是两个操作：取消分享保留个人原片；逻辑删除使本人也不能新选用。首期不实现物理清理，保留任务快照和必要的进行中任务文件；分享不会把存储所有权转给调用者。

### 12.6 实施范围与验收

首期必须形成两个相互独立但可组合的闭环：专员封装公共目标、普通用户上传管理并分享原片。建议顺序为数据与授权模型 → 两个素材入口与个人上传 → 分享 / 撤回和受控原片查询 → 专员封装发布 → 模板组合调用与状态恢复。搜索、改名和回收站按个人管理范围落实，永久删除与跨组织分发以后再做。

| 验收场景 | 通过标准 |
| --- | --- |
| A 上传未分享原片 | 只在 A 的个人区；B 的公共和个人列表、直接 ID 请求均无法读取或调用 |
| A 分享一条原片 | A 仍保有归属，个人区标已分享；B 公共区可见可用；A 的其他私人原片不公开 |
| B 使用 A 的分享原片 | 与专员发布的对象组合，生成准备快照归 B，A 看不到 B 的任务与结果 |
| B 管理他人原片 | 改名、分享切换、删除均被后端拒绝 |
| 普通用户调用未封装目标 | 散图、无包或伪造包引用仍拒绝；原片分享不扩大封装权限 |
| A 取消分享 / 移入回收站 | 公共新查询排除；旧链接、旧选择和缓存不能绕过准备 / 执行检查；已有任务按上述规则保留 |
| 分享响应丢失或并发撤回 | 读取权威状态或按版本冲突恢复，不报假成功，不重复创建记录 |
| 同一原片从两类入口被选中 | 同一批任务按 ID 去重；两类入口不复制原件或重复计算本人容量 |
| 加载失败与个人空 / 公共空 | 三种情况分别呈现；缓存保留，就地重试可恢复 |
| 历史记录迁移 | 原有个人素材默认私有；不自动分享、不改变素材或任务归属 |

本节为已确认业务规则及标明的管理建议；当前仅修订文档，未修改业务代码、未新增接口、未验证运行行为。
