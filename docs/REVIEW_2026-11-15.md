### 1.2 `model_driver` 三个端点没有归属校验（跨用户 IDOR + 可取消/重跑他人付费任务）

- **file:line** — `api/src/modules/model_driver/service.py:109`（`query`）/ `:114`（`cancel`）/ `:136`（`retry`）：三处都只有 `job = await session.get(DriverJob, task_id)`，无 owner 判定；路由 `api/src/modules/model_driver/router.py:38-40` 只挂模块级权限 `model_driver:read / cancel / create`。
- **对照（同一仓库的既定口径）** — `api/src/modules/task/service.py:98`：`task.author_id == actor.id or actor.has(PERM_READ_ALL)`；`api/src/modules/image/service.py:304`：`job.owner_id != actor.id and not actor.has(PERM_RETRY_ANY)`。
- **why** — 兄弟模块把「看自己的」与 `*:read:all` / `*:retry:any` 分成两个码，而 `model_driver` 没有 `read:all` 这一档，`model_driver:read` 天然等于「看所有人的」。利用路径：拿 `model_driver:read` 的账号对任意 `task_id` 调 `GET /model-driver/tasks/{id}` → 响应带 `output_url`（S3 驱动下是**别人的预签名直链**）、`external_id`（上游任务号）、`owner_id`；调 `POST .../cancel` → 真的去调 `provider.cancel(external_id)` **取消别人正在跑的供应商任务**；调 `POST .../retry?confirmCharged=true` → 让别人已计费的作业重新提交，费用记在原主名下。
- **缓解事实** — 该码不在任何内置角色里（需显式授予个人），前端也无对应页面 → 是 API 面 IDOR，不是现成利用链。
- **fix** — 照 `task` / `image` 补 owner 判定（`job.owner_id != actor.id and not actor.has("model_driver:read:all")` 拒绝）；`cancel` / `retry` 另设 `model_driver:cancel:any` / `model_driver:retry:any`；`retry` 与 `image` 一样受 `confirmCharged` + `retry:any` 双闸门约束。

### 1.3 限流重投丢掉幂等键 → 同一记录可能出现两条并发付费提交

- **file:line** — `api/src/generation/runner.py:336-344`（`19efdbd` 引入）：
  ```python
  await self._queue.enqueue(Job(name=job.name, payload={**job.payload, "throttle_retries": used + 1},
                                 max_attempts=job.max_attempts, timeout_sec=job.timeout_sec), delay=delays[used])
  # ← 没有 idempotency_key
  ```
- **证据链** — `Job.idempotency_key` 默认 None（`api/src/infra/queue/base.py:78-96`）；`dispatch()` 建的提交 job 带键 `submit:{kind}:{record_id}`（`runner.py:159-166`）；队列去重**只在键非空时生效**（`api/src/infra/queue/db.py:255-270`）；`ack()` 把父行删掉 → 键被释放（`db.py:500-504`）；`handle_submit` 的唯一防线是 `record.submitted`（看 `external_id`），两条 job 并发时都读到空 → **两次 `provider.submit()`**；`worker_concurrency` 默认 2（`core/config.py:239`）正好允许并发领取。
- **why** — 触发条件：上游 429 / 队列满（`19efdbd` 的 commit message 记录用户刚踩到）+ 进程重启（`QUEUE_DRIVER=db` 时无键 job 存活，巡检 `modules/image/maintenance.py` 再 `dispatch()` 出一条带键的）。这是付费视频/生图的双计费路径。
- **fix** — 重投时保留 `idempotency_key=job.idempotency_key`，让队列走 continuation 分支把这一跳写进父行 `next_job`（`ack` 原地提升为 pending），与 `_schedule_poll` 的 `poll:{kind}:{record_id}` 同一套做法。

## 5. 复核为干净的部分（避免重复劳动）

- **认证生命周期**：令牌不烤死权限 —— 每请求经 `api/src/api/deps.py` → `api/src/api/authn.py` → `modules/identity/principal.py` 回库重解析（`resolve_identity()`）；停用账号、会话被吊销（`sessions.active_by_id` 查 `revoked_at`）、改密前签发的票**立即生效**，不存在 2 小时窗口。
- **越权面**：AST 扫过全部 60 个 POST/PUT/PATCH/DELETE 路由，**每个都挂了权限依赖**，无裸写接口。共享审批在服务层按全站/团队/小组三档判定（`_can_approve_target`）并用 `UPDATE … WHERE status='pending'` + `rowcount==1` 抢占。`scope=all` 仅在持 `:read:all` 时生效（`task/repository.py:36-45`、`image/feed_provider.py:53`）。
- **迁移链**：48 个版本文件，单 head `a7d3f0c85e21`，无缺失父节点、无分叉；唯一不可逆的 `b8e4c1f90d27` 的 `downgrade` 明确 `raise RuntimeError`，CI 的降级锚点 `alembic downgrade b8e4c1f90d27` 与之相符；sqlite 上 `upgrade head → downgrade → upgrade head` 实跑通过。
- **SSRF 护栏**：生图产物的 `persist_output` 每跳重跑 `_validate_asset_url`，且生产强制配 `allowed_hosts`（`modules/image/pipeline.py:92`）；libtv 与 pg_dump 都是 argv 数组、无 `shell=True`。
- **路径与打包**：本地存储 key 白名单 + 拒绝 `..` 段 + `is_relative_to`；归档 `within()` 拒绝绝对路径；zip 条目名过 `_safe_name`（剥 `/ \ : * ? " < > |` 与控制字符）→ 无 zip-slip。
- **队列**：DB 队列有 fencing token（`lease_token`）、条件领取与回执 `rowcount` 检查、续接落空有兜底。
- **契约**：四份生成物零差异；旧替换链端点（`/templates/replacement-*`、`/video-templates`、`/template-manifests`）全部 404。
- **生产自检**：弱密钥 / 匿名 / 无 `METRICS_TOKEN` / CORS 通配 / `TRUSTED_PROXIES=0.0.0.0/0` 四道闸都在；`JWT_SECRET` 样例值前缀被 `("dev-only","change-me")` 覆盖。
- **前端权限判定**：`shared/access/evaluate.ts` 与后端 `CurrentUser.has` 的通配语义一致（前端更宽的那部分因后端只接受目录内码而不可达）。
- **mock 打包**：演示口令与 mock 适配器不在生产 bundle（`dist/` 里 grep 不到 `admin@12345`）。
