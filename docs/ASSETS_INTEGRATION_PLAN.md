## 1. 总目标与完成标准

建立「专员维护公共替换对象，普通用户管理并分享原片，模板统一选用」的完整流程。

最终验收流程：专员 S 封装并发布产品 / 人物 / 场景 → 用户 A 上传私有原片 → A 可自己使用，也可主动分享 → 用户 B 从公共原片选择 A 分享的内容 → B 选择专员发布的替换对象 → 保存实际输入快照并核对 → 确认执行 → 结果归 B，其他人的私人数据保持隔离。

确认本单意味着确认 T01–T07 全部目标、下述默认规则和排除项；之后按依赖顺序开发，不再对每个常规实现步骤重复请求确认。新增范围或业务规则变化另行沟通。确认不包含部署、真实上游生成或付费操作。

## 4. 页面与操作范围

### 4.1 公共素材

- 一级入口「公共素材」，下分原片、产品、人物、场景；首期不新增音频模板，已有音频归档不删除。
- 原片包含专员主动公开的原片及普通用户主动分享的原片；显示来源、名称、预览、规格及适用性，提供「用于替换」。
- 产品 / 人物 / 场景展示专员已发布对象，显示主图、名称和摘要，提供「用于替换」；不展示未发布散图与草稿。
- 搜索、类型筛选和分页由服务端按权限处理；统计只描述当前可见范围，不暴露私人数量或伪称磁盘剩余容量。
- 非维护者不出现改名、编辑、删除、取消别人分享等操作。

### 4.2 我的素材

- 普通用户上传入口仅接收原片，支持既有多文件批次与逐条反馈；模板快速上传同样保存到个人区且默认私有。
- 按名称搜索，按全部 / 私有 / 已分享筛选；本人可预览、下载原件、使用、重命名、分享 / 取消分享。
- 回收站提供移入与恢复；恢复后默认私有，原片需本人再次主动分享，不自动恢复公共曝光。
- 已分享的本人原片同时出现在公共与个人视图；同一条记录只保存一份原件。
- 原有非原片个人记录保持私有、不删除；通过本人历史素材入口保留其原有查看能力，不允许作为普通用户散图替换目标使用。

### 4.3 专员维护

- 有管理权限者可以上传 / 登记参考图，组建产品、人物、场景草稿；inbox 登记作为维护入口保留，不提供给普通任务用户。
- 可保存不完整草稿；发布时必须通过同类引用、图数、封面、文件可读与哈希校验。
- 草稿可以编辑；发布后修改形成新版本，旧任务仍保留原快照；停用阻止后续调用。
- 首期同一专员可兼有封装与发布权限，不增加强制双人审核。其他专员默认不能任意接管别人的草稿；如有需要由管理员显式授权维护范围。

### 4.4 模板与任务

- 保留现有多原片选择；两个来源选到同一 ID 时去重。
- 素材页「用于替换」可带入原片或包；只带入选择，不自动准备或执行，返回后重新校验 ID 和版本。
- 普通用户只能选择已发布对象，不能上传参考图、传任意 referenceIds 或覆盖封装固定参数。
- 模板允许的任务备注与替换范围继续可填，服务端明确其字段白名单。
- 历史任务按原归属读取输入与结果，不因原片分享而向上传者或其他人公开。

| 发布版本 | 已发布版本内容固定；明确展示与选择版本，新版本不改写已准备任务；任务执行仍检查所引用版本可用性 |
| 重复内容 | 暂不自动按内容合并；分享本身不复制文件。发布、分享等管理请求按操作标识 / 状态版本防重复，保留现有上传结果未知核对机制 |
| 历史数据 | 旧原片默认私有，旧包未经确认不公开；旧包保留维护者可见，由有权限者确认后发布；历史任务仍可查看，不静默扩大权限 |
| 角色启用 | 普通任务用户可上传及分享本人原片；专员封装 / 发布能力独立授权。交付角色配置或迁移入口，不静默修改生产角色 |

任务进入上游的最终授权检查必须与撤回操作有明确的先后边界：撤回已生效则拒绝尚未授权提交的执行；执行已越过提交边界则保留在途处理，并展示事实。不能仅在页面点击时检查，也不能持有原片锁等待整个生成完成。

## 10. 新权限如何适配现有体系（已确认并实施）

### 10.1 角色采用复用加扩展

保留现有用户、角色、多角色权限并集和后端 `require()` 判定机制，不按账号名称或固定角色名称判断业务能力。

| 角色 | 适配方式 |
| --- | --- |
| admin 超级管理员 | 保持现有超级权限；业务仍遵循数据范围、任务快照和执行状态规则，超级权限不意味着取消所有归属检查 |
| editor 内容编辑 | 作为可执行任务的普通用户：管理自己的原片、分享、使用公共内容和模板；既有任务 / 生图权限范围保留，若以后希望收紧跨用户任务管理另行定义 |
| viewer 只读成员 | 保持只读，可查看授权公共内容和本人已有记录；不能上传、分享、封装、提交生成或评价 |
| asset_specialist 素材专员（新增） | 作为附加能力角色，仅给指定人员；主要授予参考素材维护、封装与发布。需要同时执行任务的专员再拥有 editor，不用给其超级管理员 |

「普通用户」在本业务中指具备任务使用能力的账号，不等于所有非管理员账号；viewer 不自动升级为 editor。

### 10.2 精确权限与拟分配

| 权限 | 状态 / 作用 | 普通 editor | 只读 viewer | 专员附加角色 |
| --- | --- | --- | --- | --- |
| asset:read | 已有，读本人素材及被授权的公共预览 | 有 | 有 | 有 |
| asset:create | 已有，普通用户上传本人原片 | 有 | 无 | 有，参考素材仍额外检查维护权限 |
| asset:update | 新增，修改本人素材展示信息 | 有 | 无 | 有，仅在管理范围内 |
| asset:delete | 已有，落实本人逻辑删除 / 恢复，非物理删除 | 有 | 无 | 有，仅在管理范围内 |
| asset:share | 新增，分享 / 取消分享本人原片 | 有 | 无 | 无需重复授予，任务专员由 editor 获得 |
| asset:reference:manage | 新增，维护封装所需参考素材及 inbox 登记 | 无 | 无 | 有 |
| template:read | 已有，查看授权模板、已发布对象与本人替换记录 | 有 | 有 | 有，用于封装工作流展示 |
| template:use | 已有，准备 / 执行模板任务 | 有 | 无 | 不单独授予；要生成则同时配置 editor |
| template:review | 已有，评价自己的替换成片 | 有 | 无 | 不单独授予；由 editor 获得 |
| template:pack:manage | 新增，创建、编辑和保存管理范围内的封装草稿 | 无 | 无 | 有 |
| template:pack:publish | 新增，发布新版本、停用管理范围内的对象 | 无 | 无 | 有 |

专员上传参考图需同时具备 asset:create 与 asset:reference:manage；普通用户即使直接向上传接口传人物 / 产品 / 场景分类，也不能绕过。普通原片上传不要求参考素材维护权限。原有音频等记录保留本人查看，不额外向普通用户开放参考素材维护。

发布需同时具备 template:pack:manage 与 template:pack:publish，并满足维护范围；后端与页面分别落实。管理范围不默认包含其他专员的草稿或全站私人素材。普通内容编辑使用模板仍只能选择已发布包，不提供散图通道。

### 10.3 必须处理现有通配授权

实施前 editor 存在 `asset:*`；若不迁移就新增 asset:reference:manage，editor 会自动拥有这项专员能力。现已收敛本地开发角色授权，其他环境启用前须显式迁移。

拟在本次适配中将 editor 的 `asset:*` 替换为精确的 `asset:read / asset:create / asset:update / asset:delete / asset:share`。保留其既有其他模块授权；新内置角色模板与已存在数据库都要处理。普通角色不授予 `template:*`。

检查其他自定义角色是否持有 `asset:*`、`template:*` 或 `*`，报告其新增权限影响，由管理员确认是否保留通配意图；不能只更改 editor 就宣称所有普通账号已隔离。用户多角色的权限取并集，要以最终有效权限验收，不能只看某一个角色。

实施前本地数据库 editor 缺少 template:use 和 template:review；本轮已显式补齐。其他环境始终重新预览差异，不能直接套用本地快照。

### 10.4 权限不代替资源授权

- 有 asset:share 仍只能分享本人未删除的原片；不能分享别人的记录或封装参考图。
- 有 asset:read 不等于读取全站私人素材；读取路径为本人素材、有效分享原片或已发布包的受控预览。
- 有 template:use 仍需校验原片可用性、包已发布且版本可调用、固定配置、零积分门禁与提交状态。
- 封装专员不是用户管理员；不因授予专员角色附送 identity:*。
- 分享撤回与包停用不能只靠隐藏按钮，准备和最终提交边界都检查当前资源授权。

### 10.5 实施与验收方式

先注册权限目录和角色默认模板，再提供只读差异预览及显式、可重复执行的迁移入口。差异报告列出角色权限增减、受影响账号及自定义通配角色；实际应用记录原配置，支持按版本检查后回滚，避免覆盖管理员后续变更。

不能只依赖现有「补齐内置权限」命令：该命令只加不减，无法移除 editor 的 asset:*。本次需要明确替换该通配的迁移逻辑；应用重启仍不能静默改写角色。

角色分配通过现有「用户与权限」页面完成，由具备角色管理能力且有权授予这些权限的管理员操作。确认后已迁移本地开发库 editor 的素材权限，未自动给账号分配专员角色；备份及生产操作边界见第 11 节。

验收至少包含 admin、editor、viewer、editor + asset_specialist，以及带自定义通配的角色；验证页面入口与直接 API 请求，确认 editor 能分享原片但不能维护参考图或发布包，专员能封装但没有用户管理权。
