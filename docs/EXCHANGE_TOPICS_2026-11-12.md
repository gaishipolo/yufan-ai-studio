# 跨公司交流 · 可聊的问题清单

> 2026-11-12 下午。基于 `yufan-ai-studio` 当前 `main`（`d3235df`）整理。
>
> 用法：先用 §1 讲清我们是什么，然后按 §3 挑 3~4 组问——**不要全问**，
> 交流的价值在于对方能答得深，不在于我们问得多。

---

## 1. 三十秒讲清我们做了什么

一个**单组织部署**的 AI 内容生产工作台，不是"AI 生图工具"，是"把内容生产流程搬进系统"：

| 维度 | 现状 |
|---|---|
| 规模 | 12 个业务模块 · 118 条路径 / 148 个端点 · 57 个权限码 · 1570 条后端测试 |
| 模型层 | 插件化：**放一个 py 文件 = 接入一个供应商**，不改 `.env`、不改 import |
| 已接供应商 | Agnes（图 / 视频）、百炼、LibTV + 本地占位 echo |
| 核心链路 | 模板库 → 替换配置 → 产品替换（上传参考图 → 估价 → 提交上游 → 轮询 → 下载），拆成 5 段异步 |
| 资产治理 | 素材库三级可见性（个人 / 小组 / 团队）+ 封装共享 + 审批 + 回收站 + 文本资产 |
| 技术栈 | FastAPI + SQLAlchemy 2.0 async + PostgreSQL + React/Vite |

**开场建议一句话**：
> 我们做的不是"接一堆模型"，而是把"谁能用哪个模型、生成的资产归谁、花了多少钱、出了问题怎么查"
> 这套东西做成系统。模型反而是最容易被替换的一层。

## 2. 我们踩过的最值得讲的三件事

放在前面，因为它们能让对方立刻判断"这家遇到的坑跟我像不像"。

### 2.1 「可见性」从来不是二元的

模型目录里，一个模型对用户可见与否，我们最后需要**三个状态**：

| 状态 | 含义 | 例子 |
|---|---|---|
| 公开 | 正常可选 | `agnes-image-2.5-flash` |
| `internal` | 只能自己的业务链路调，露脸必然 400 | 替换链专用的 `libtv-wan3-*`（要带 `archiveRunId`） |
| `placeholder` | **实现是假的**，露脸不报错但结果是假的 | 本地占位供应商 echo 的 `seedream-3` |

第三类是最坑的：用户在下拉里选「Seedream 3」，跑完拿到 `example.com/mock/` 的占位图，
**全程没有任何报错**，看起来像真接了豆包。我们是靠用户自己发现"这几个模型好像没实现"才查出来的。

**更狠的连带问题**：默认模型原来取"第一个注册进来的"，而占位供应商注册顺序靠前
→ 默认视频模型是个假模型 → 前端看不到默认标记 → 不传 model → 后端按默认取到假模型
→ 出假图且不报错。最后把规则收紧成「**默认模型必须公开且真实**」，没有就宁可没有默认。

### 2.2 付费任务的失败语义，影响的是钱不是体验

模型下线时，"当场判失败"还是"退避重试"看起来是体验问题，其实是**计费问题**：

- 普通生成任务：当场失败对（退避到最后用户只看到"生成超时"，指不出真因）
- **替换链是已付费任务**：判失败会诱导用户点重试 → **重复计费**

所以我们做成流水线级声明式开关 `fail_on_model_gone`，替换链单独声明 `False`。
同一个异常类型，两条链路两种语义。

### 2.3 一类「口径不对但不会报错」的 bug

我们做过一次全面只读审查，产出 P0×2 / P1×9 / P2×11。修完之后复盘发现，
**最难发现的一类不是崩溃，是"结果不对但你不知道"**：

- 长文案任务"已完成但草稿箱里没有"——因为存提示词那列是 `String(4000)`，超长被截了
- "成功但订阅方收不到事件"——因为超时块把落库之后的归档也包进去了，超时被跳过
- 队列链路静默断掉、记录永久 `running`——因为续接时没查 rowcount，父行已被 ack 删了

这三个的共同点：**没有一个抛异常**。它们只在真实数据量、真实慢盘、真实并发下才出现。

## 3. 建议问的问题（按价值排序，挑 3~4 组）

### 第 1 组：内容合规与审核 —— 我们完全没有，最想听

**我们的现状**：零审核。生成的图/视频直接落库、直接能下载。上游供应商有它们自己的合规策略，
但我们侧没有任何拦截、没有敏感词、没有人工复核队列。

**想问**：

1. 企业客户用 AI 生成内容，**审核放在哪一层**？是让供应商拦、我们侧过一遍模型审核、
   还是纯人工抽检？三者的成本差多少？
2. 如果做机器审核，**是在生成后审、还是提交前就审 prompt**？生成后审意味着钱已经花了。
3. 审核不通过的内容**怎么处置**？直接删、留档给客户看、还是标"待复核"？
   有没有遇到过"客户坚持认为没问题、但我们不敢放"的情况？
4. **供应商侧的审核能力**（比如阿里云内容安全）实际误杀率如何？中文场景下可不可用？

> 这组问题是纯求教。我们这块是空白，任何一条经验都比我们自己摸索强。

---

### 第 2 组：成本归因 —— 我们只有一个粗粒度"积分"

**我们的现状**：替换链有 `billing_mode`（`free` = 0 积分权益队列 / `credits` = 走积分加速队列），
但**没有按任务 / 按人 / 按项目的成本核算**。也就是说：这个月谁花了多少钱，我们答不上来。

**想问**：

1. 企业客户一定会问"这个月内容部花了多少"，你们**怎么归因**？
   按任务记单价 × 数量，还是按供应商账单反向摊？
2. 不同模型单价差异巨大（一张图几分钱到几毛钱），**预算控制**做在哪一层？
   提交前预检余额、还是事后告警？
3. 有没有做「**额度包 / 配额池**」给部门或项目？额度不够时是拦死、还是降级到便宜模型？
4. 如果一个任务失败了但供应商已经扣费（我们的替换链就按这个假设设计的），
   **这笔钱算谁的**？有没有对账机制？

---

### 第 3 组：多实例与队列 —— 我们有一份明确的"硬边界"清单

**我们的现状**：这条值得讲，因为我们的结论比较反直觉——**能跑，但不能无脑横向扩**。

队列用 db 驱动 + 轮询（0.2s 起、退避到 1.0s），同进程有 `asyncio.Event` 唤醒，
**跨进程唤醒没做**（要 0 延迟只能靠 PG 的 `LISTEN/NOTIFY` 或 Redis，而我们同时支持 sqlite，
接 `LISTEN/NOTIFY` 会变成两套取任务路径）。

三处**结构性硬边界**（不是遗漏，是明确留下的）：

| 边界 | 具体问题 |
|---|---|
| 配额非原子 | PG 下用 `FOR UPDATE` 串行化"读 sum → 判上限 → 写行"，但用户**首次**登记时无行可锁 |
| 预签名 TOCTOU | 先 `exists()` HEAD 再 307，另一个实例的 GC 可能在这两步之间删掉字节 |
| 运行工作区仍是共享盘 | 执行器（ffmpeg / node）需要**真实本地文件**，云化等于重写执行器输入层 |

**想问**：

1. 你们队列用**自建还是托管**（Temporal / Celery+Redis / SQS / Cloud Tasks）？
   选型时最看重的是什么——延迟、可观测、还是"不用自己维护"？
2. 「入队到开始执行」你们的 **P99 是多少**？我们的最坏情况被退避封顶在 1 秒，
   不确定这在内容生产场景算不算问题（用户本来就要等 30 秒以上）。
3. 有状态的长任务（我们一条链路 5 段异步、中间状态写在共享盘 `run.json` 里，不靠 DB），
   你们是怎么做**崩溃恢复**的？编排引擎自带，还是自己写？
4. 多实例下**配额扣减**你们用乐观锁还是条件 UPDATE？有没有踩过超扣？

### 第 4 组：模型抽象层 —— 我们做了一版，想验证是否过度设计

**我们的现状**：接入一个供应商 = 在 `drivers/` 放一个 py 文件，声明 `META` + `MODELS` + 三个方法
（`submit` / `poll` / `cancel`），自动发现、自动注册。业务模块**只认 `ModelSpec` + 路由器**，
不拿供应商实例。

**踩过的坑都指向同一件事：不是接口难统一，是"口径"难统一。**

- 默认模型不能靠"注册顺序"，必须由供应商声明 `preferred_for`——否则新增一个驱动会
  **静默**改变默认模型（我们真踩过：默认生图差点变成占位模型的 `seedream-3`）
- 同步供应商（图片，一次等 13 秒）和异步供应商（视频，拿任务号轮询）要同一套协议
- 参数区完全由 `GET /models` 的 `paramSchema` 渲染，**新增参数不改前端**；
  但未声明的键必须 400 + 告诉前端可用参数，否则 `szie` 这种拼写错误会静默失效

**想问**：

1. 你们怎么处理**同步 / 异步供应商混用**？我们让 `submit` 返回 `str`（要轮询）或终态快照（不轮询）两种类型，感觉有点丑但实用。
2. 模型能力差异很大（有的支持参考图、有的支持首尾帧、有的只能文生），
   这些能力**声明在 schema 里还是散在代码里**？我们的参考图数量是独立字段，因为参数 schema 装不下一批图片。
3. 有没有遇到过「**同一个模型名，不同供应商效果差很多**」，用户投诉时你们怎么定位？
4. 我们做这套抽象花了不小代价。**如果你们只有 2~3 个供应商，会做这层抽象吗**？
   还是直接 if-else 更省事？

### 第 5 组：资产权限模型 —— 「共享」和「可见」是两件事

**我们的现状**：三级可见性 `personal` / `group` / `team`，团队 ⊇ 小组；
封装（pack）可以把自己的素材共享出去，但**成员自己的 `visibility` 仍是 `personal`**
——共享是"额外开一扇门"，不是"改归属"。

审批权限码按**申请单的目标范围**拆开（全站 / 团队 / 小组），因为"能批全站的人"
和"能批我所在小组的人"是两个不同的信任级别。

**想问**：

1. 素材的归属你们是**单一 owner + 授权表**，还是**可见性字段 + 成员表**？
   我们选了后者，代价是"一条资产能同时出现在个人、小组、团队三个入口"，角标加了不等于总数
   （去重导致）。你们有没有更干净的做法？
2. 员工离职 / 调组之后，他创建的素材归谁？我们目前有个已知问题：**被移出小组后
   owner 看不到自己的素材**（产品口径没定，暂按现状）。
3. 有没有做**跨部门共享**？如果 A 部门要借 B 部门的素材，走审批、还是走"申请加入"？

## 4. 我们能反向给对方的（交流是双向的）

这部分建议主动说，不然容易变成单向取经。

1. **模型驱动插件化**：一个文件接入供应商、不改配置不改 import、单文件出错不拖垮服务
   （逐文件 try/except，失败在 `app drivers check` / `app doctor` 里暴露）。
2. **三级可见性 + 独立标记**：`internal`（露脸必 400）和 `placeholder`（实现是假的）
   分开，因为两者的失败方式完全不同。
3. **「默认值必须公开且真实」**这条规则本身——它防的是"用户不传参数时后端替他选了个不能用的"。
4. **测试范围工具**：1570 条测试全量 169 秒嫌慢，做了个按 git diff + import 依赖图自动算
   "这次该跑哪些"的脚本，定向 20 秒。关键是**用"还原改动后守卫必须变红"验证了判别力**。
5. **文档即约束**：我们把"如果不这样写就会静默出错"的结论写成不变量清单，
   而不是写功能说明。

## 5. 别问的（省时间）

- ❌ "你们用什么技术栈" —— 信息量低，五分钟就聊完了
- ❌ "AI 未来怎么看" —— 谁都答得出来，但没人有答案
- ❌ "提示词怎么写效果好" —— 太业务、太个人经验，不适合跨公司
- ❌ "你们模型接了几家" —— 数量不说明问题，接 3 家做得好比接 20 家做不好强

## 附：我们项目的已知缺口（对方问到别慌，直接承认）

| 缺口 | 说明 |
|---|---|
| 内容审核 | 完全没有 |
| 成本归因 | 只有粗粒度积分，没有按任务/人/项目核算 |
| 多租户 | **单组织部署**，没有 `tenant` / `org_id` 概念。"给多家公司用"要改数据模型 |
| 跨进程队列唤醒 | 只有进程内 Event，多实例下最坏延迟 = 退避封顶值 |
| 多实例配额原子性 | PG 下基本够用，首次登记无行可锁 |
| 内容质量评测 | 没有 eval / 人工评分闭环，只有"生成成功/失败" |
